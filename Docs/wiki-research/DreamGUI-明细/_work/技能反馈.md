- **哪一步**：把「功能全集」的**覆盖面判据**定成「每个反射类型的**全名**必须出现在账本里」。
- **技能当时怎么说的**：`SKILL.md` §12.1 给了三查（schema 漂移 / 悬空引用 / 数值不变量），`完成判据.md` 里有详表但本轮没读（按 §11.1 的预算被砍掉）。**三查里没有「条目覆盖率」这一项**。
- **我实际怎么做的**：自己写了一个逐类型子串命中的复算脚本，把它当作本专题的**第四查**，并把命令与两轮结果（72.7% → 100%）写进 `03_变更与缺口.md`。
- **为什么**：选题卡第 ③ 条的 Q1 就是「370 个类型分别属于哪个功能域（机械全枚举，一个不漏）」——不自己量一遍，就无法回答「补完了没有」。

- **哪一步**：发现 101 个类型缺失后，判断根因是**简写**而不是「我漏了功能」。
- **技能当时怎么说的**：`素材账本字段.md` §6 三条红线里有「不整段抄」，`COL-R05` 要求「证据够核对即可」。这两条**鼓励简写**。
- **我实际怎么做的**：在「枚举清单」这种特定断言上**放弃简写**，把 15 处 `_Suffix` 展开成完整类名，产物变长了。
- **为什么**：`COL-R05` 管的是**证据**（够核对即可），而「有哪些 X」是**枚举断言**——枚举断言的完整性本身就是要交付的东西，简写会让它失去可机检性。**这两类文本的写法要求其实相反**，技能里没有区分。

- **哪一步**：把「未声明」与「不一致」在检查器里分开。
- **技能当时怎么说的**：`规则契约.md` 把「本地可证明的 ID／引用／枚举／算术矛盾」列为 `structural_invariant`（脚本可阻断）。没说清「账本没抄这个数」算哪一档。
- **我实际怎么做的**：改成「声明值缺失 → advisory；声明值不一致 → major」。
- **为什么**：拆成两个专题后，专题 B 的账本起初没有抄那组机械基线，检查器直接报了 3 条 major——那不是「矛盾」，是「本次没比」。

## 4. 一次自我更正（留给技能作者当素材）

我一度在账本里写下「`DECLARE_DREAM_GUI_VISUAL` 不存在」。根因是我用「两个字符串参数」的正则去匹配这个宏，而它是「一个字符串 + 一个类型」两个参数 —— **解析到零被我当成了「不存在」**。这正是 `素材账本字段.md` 开头那句「**别把『解析到零』当『检查通过』**」的翻版，只不过这次犯在**否定方向**上：把零命中当成否证。

技能里那条警告只举了「检查通过」的方向，没有覆盖「据此断定某东西不存在」的方向 —— 而后者更危险，因为它会直接写进账本。
