# 零境交错数值设计参考

> 本文用于整理《零境交错》的养成基准、基础属性、战斗公式、技能倍率、资源经济与关卡数值。内容按照设计者提供的信息逐步补充；尚未确认的部分保持空缺，不根据现有角色个例反推为正式规则。

## 一、文档用途

角色设计不能只判断机制是否符合人物，还需要把技能和被动换算到同一数值尺度中。本文最终需要回答：

- 不同品质和养成结果提供多少基础属性。
- 不同费用、目标范围与攻击次数的技能应当拥有多少总倍率。
- 破盾、减速、麻痹、扣除技能点等效果需要交换多少伤害。
- 一名角色在短战、长战和不同编成中的实际回合收益。
- 角色数值是否迫使玩家采用唯一养成、唯一技能顺序或唯一队伍。

当前首先记录局外养成和基础属性。

## 二、品质与重复获取

### 1. 品质顺序

角色首次获得时默认为 **D级**。之后重复获得同一角色，可以依次提升品质：

> D → C → B → A → S

品质同时影响：

- 角色的初始基础属性。
- 本次养成中可以分配的技能升级次数。

所有技能的等级上限统一为5级，品质不会改变单个技能的等级上限，只会改变一次养成可以获得并分配的技能升级次数。

### 2. 重复养成

角色养成采用接近《赛马娘》的重复养成思路。玩家并非完成一次固定培养后永久得到唯一答案，而是可以针对不同队伍、关卡和玩法目标重新养成角色。

因此，生命值、攻击力和技能等级分配不仅是成长进度，也属于角色构筑选择。某些机制可以读取玩家的养成结果，例如御坂美琴可以通过生命值投入影响拼刀胜负倾向。

重复养成能够承载差异化构筑，但需要避免：

- 某一种属性分配在所有环境中固定最优。
- 正常提高属性反而永久破坏角色玩法。
- 玩家在养成结束后才发现技能等级分配无法支持预期循环。

### 3. 单次属性选项数值

一次养成具体拥有多少次培养机会会根据实际模式和回合安排变化，不设置固定次数。系统根据总回合数、是否为特殊事件和属性模式，自动计算当前选项提供的属性值。

令总回合数为 `RoundAll`，由于C++使用整数除法：

```text
分母 R = floor(RoundAll / 3)
```

每次选项获得的数值为：

```text
AbMode = 0，攻击力：
普通选项 = floor(320 / R)
特殊事件 = floor(960 / R)

AbMode = 1，生命值：
普通选项 = floor(8000 / R)
特殊事件 = floor(10000 / R)

其他AbMode，次级属性：
普通选项 = floor(3000 / R)
特殊事件 = floor(5000 / R)
```

这套公式会根据总回合数反向调整单次收益：养成回合越多，每次选择提供的属性越少；养成回合越少，单次选择提供的属性越多。

当前没有足够的实际养成样本，暂时不写“S级角色正常毕业属性”。后续应从真实养成结果统计常见区间，而不是用理论上限代替。

### 4. 战斗给予技能升级点

完成一次养成战斗后，会获得0至10个技能升级点。玩家随后在一技能、二技能、升华技和护援技之间自行分配。

技能升级点的实际数量由战斗结果或对应规则决定，当前尚未记录0至10各档的具体判定条件。

## 三、技能等级

### 1. 初始等级

角色获得时，每个技能默认均为 **1级**。

技能升级由玩家自行选择，不会按照固定顺序自动提高。不同养成结果可以把升级次数集中给主力技能，也可以在多个技能之间平均分配。

### 2. 各品质升级次数

| 品质 | 可分配的技能升级次数 |
| --- | ---: |
| D | 6次 |
| C | 8次 |
| B | 10次 |
| A | 12次 |
| S | 16次 |

玩家可以升级四个技能：

- 一技能。
- 二技能。
- 升华技。
- 护援技。

每个技能初始为1级，上限为5级。从1级升到5级需要4次升级，四个技能全部升满一共需要16次。

因此：

- D、C、B、A品质仍然需要在四个技能之间分配有限升级次数。
- S品质拥有16次升级，可以把四个技能全部提高到5级。

S品质允许全技能升满是后续调整后的正式规则，不再强迫最高品质玩家为了保留局内升级空间而故意留下未满技能。未来角色仍然可以在局内提高尚未满级的技能，但任何方式都不能使单个技能超过5级上限。

### 3. 品质提升后的技能养成

品质提升会追加对应的初始属性，但新增的技能升级次数不会自动替玩家分配。玩家需要重新进行养成，再为四个技能加点。

因此，品质提升同时包含两种变化：

- 初始属性直接提高。
- 技能等级需要通过新一次养成重新规划。

### 4. 连携技等级

连携技不能直接分配升级次数。系统读取Main和Sub各自四个技能的等级总和，再计算连携技等级。

令Main四个技能等级总和为 `SM`，Sub四个技能等级总和为 `SS`，则：

```text
总技能等级 = SM + SS

总技能等级 > 8：
连携技等级 = floor(总技能等级 / 8)

总技能等级 <= 8：
连携技等级 = 1
```

C++整型除法会自动舍去小数部分，因此对应区间为：

| Main与Sub技能等级总和 | 连携技等级 |
| ---: | ---: |
| 8至15 | 1 |
| 16至23 | 2 |
| 24至31 | 3 |
| 32至39 | 4 |
| 40 | 5 |

Main与Sub八个技能全部1级时，总和为8，连携技为1级；八个技能全部5级时，总和为40，连携技为5级。

## 四、品质初始属性

### 1. 原始数值

| 品质 | 生命值 | 攻击力 | 暴击率 | 暴击伤害 | 物理防御 | 异能防御 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| D | 2000 | 50 | 10 | 10 | 50 | 50 |
| C | 2500 | 60 | 30 | 30 | 60 | 60 |
| B | 3000 | 75 | 60 | 60 | 80 | 80 |
| A | 4000 | 85 | 80 | 80 | 100 | 100 |
| S | 4600 | 100 | 100 | 100 | 200 | 200 |

生命值和攻击力直接使用表中数值。暴击率、暴击伤害、物理防御和异能防御是换算前的原始属性，需要经过分段公式转换为实际比例。

品质提升后，会把角色的初始属性提高到对应品质的基础水平。已经获得的更高品质不会直接替玩家完成新的技能加点，技能部分仍需重新养成。

### 2. 初始属性换算结果

| 品质 | 实际暴击率 | 实际暴击伤害 | 实际物理防御 | 实际异能防御 |
| --- | ---: | ---: | ---: | ---: |
| D | 0.2% | 0.2% | 2.0% | 2.0% |
| C | 0.6% | 0.6% | 2.4% | 2.4% |
| B | 1.2% | 1.2% | 3.2% | 3.2% |
| A | 1.6% | 1.6% | 4.0% | 4.0% |
| S | 2.0% | 2.0% | 8.0% | 8.0% |

以上百分比是代码返回的小数比例换算为百分数后的结果。例如D级物理防御原始值50，公式返回0.02，即2%物理防御。

目前只能确认“暴击伤害属性换算结果”为表中比例，尚不能确认它在最终伤害公式中是独立加成，还是会与一个固定基础暴击倍率相加。

## 五、养成属性上限

### 1. 单个角色养成上限

| 属性 | 单个角色养成上限 |
| --- | ---: |
| 攻击力 | 1800 |
| 生命值 | 18000 |
| 暴击率原始值 | 9100 |
| 暴击伤害原始值 | 9100 |
| 物理防御原始值 | 9100 |
| 异能防御原始值 | 9100 |

此前记录的18200不是单个角色养成上限，而是Main与Sub组合以后，四项次级属性能够参与战斗计算的双人上限。

### 2. Main与Sub双人上限

| 属性 | 双人计算上限 | 上限对应实际比例 |
| --- | ---: | ---: |
| 暴击率原始值 | 18200 | 58% |
| 暴击伤害原始值 | 18200 | 58% |
| 物理防御原始值 | 18200 | 80% |
| 异能防御原始值 | 18200 | 80% |

单个角色将某项次级属性养到9100时，对应：

- 实际物理防御或异能防御为43.6%。
- 实际暴击率或暴击伤害为30.7%。

Main和Sub相同属性都达到单人上限时，合计18200，才会到达80%防御或58%暴击属性。

这些是单项属性达到上限后的结果，不代表一名角色能够在同一次养成中同时把所有属性提高到上限。养成资源总量和各属性成长成本尚未记录。

### 3. 战斗结算钳制

组合属性、BUFF或其他效果使次级属性超过18200时，战斗结算仍然按照18200计算。其他具有明确上限的数值也遵循相同原则：超过上限的部分不会继续进入实际公式。

## 六、Main与Sub属性组合

Main与Sub组成角色组合后，双方所有属性直接相加，包括：

- 生命值。
- 攻击力。
- 速度。
- 暴击率。
- 暴击伤害。
- 物理防御。
- 异能防御。

战斗中的技能伤害、行动速度和其他属性判定均使用组合后的数值，不只读取Main属性。

Main与Sub品质不同不会触发额外修正。品质只通过双方各自已经拥有的实际属性影响结果，系统只计算数值相加后的组合属性。

次级属性先将Main与Sub原始值相加，再按照18200的双人上限钳制，最后换算为实际百分比：

```text
组合原始属性 = Main原始属性 + Sub原始属性
有效组合属性 = min(组合原始属性, 18200)
```

攻击力、生命值与速度同样直接相加；它们在组合后的额外结算上限目前尚未单独记录。

## 七、防御换算公式

物理防御和异能防御使用同一套公式。令进入战斗公式前的原始防御为 `x`，首先钳制：

```text
xe = min(x, 18200)
```

再根据有效原始防御 `xe` 计算实际比例 `D(xe)`：

```text
xe <= 200：
D(xe) = xe × 0.0004

200 < xe <= 18200：
D(xe) = xe × 0.00004 + 0.072
```

如果要显示为百分数，需要再将 `D(x)` 乘以100。

### 1. 关键节点

| 原始防御 | 实际防御 |
| ---: | ---: |
| 0 | 0% |
| 50 | 2% |
| 100 | 4% |
| 200 | 8% |
| 1000 | 11.2% |
| 5000 | 27.2% |
| 9100 | 43.6% |
| 10000 | 47.2% |
| 18200 | 80% |

### 2. 分段意义

- 0至200区间每增加100原始防御，提高4个百分点实际防御。
- 200以后进入较缓慢的线性成长，每增加1000原始防御，提高4个百分点实际防御。
- 初始品质主要分布在第一段，S级正好位于第一段末端。
- 单个角色养成上限9100位于第二段中部，对应43.6%防御。
- Main与Sub双人计算上限18200位于第二段末端，对应80%防御。

### 3. 超出上限

原始防御超过18200时，有效值仍固定为18200，实际防御保持80%，不会继续提高或改用其他区间。

## 八、暴击率与暴击伤害换算公式

暴击率和暴击伤害使用同一套公式。令原始属性为 `x`，首先钳制：

```text
xe = min(x, 18200)
```

再根据有效属性 `xe` 计算实际比例 `C(xe)`：

```text
xe <= 200：
C(xe) = xe × 0.0002

200 < xe <= 18200：
C(xe) = xe × 0.00003 + 0.034
```

如果要显示为百分数，需要再将 `C(x)` 乘以100。

### 1. 关键节点

| 原始属性 | 实际暴击率或暴击伤害 |
| ---: | ---: |
| 0 | 0% |
| 50 | 1% |
| 100 | 2% |
| 200 | 4% |
| 1000 | 6.4% |
| 5000 | 18.4% |
| 9100 | 30.7% |
| 10000 | 33.4% |
| 18200 | 58% |

### 2. 分段意义

- 0至200区间每增加100原始属性，提高2个百分点实际比例。
- 200以后每增加1000原始属性，提高3个百分点实际比例。
- 初始品质提供的暴击率和暴击伤害均处于第一段。
- 单个角色养成上限9100对应30.7%。
- Main与Sub双人计算上限18200对应58%。

### 3. 超出上限

暴击率或暴击伤害原始值超过18200时，有效值仍固定为18200，实际比例保持58%，不会继续提高或改用其他区间。

## 九、技能倍率与攻击次数

技能文本中的伤害倍率表示 **每一次攻击的伤害倍率**，不能只读取一个倍率数字作为整项技能的总伤害。

若一个技能拥有 `n` 次攻击，并且每次攻击倍率均为 `m`，则不考虑其他修正时：

```text
技能总基础倍率 = n × m
```

若各次攻击倍率不同，则应逐次相加：

```text
技能总基础倍率 = m1 + m2 + ... + mn
```

因此比较技能数值时，至少需要同时记录：

- 每一级的单次物理倍率。
- 每一级的单次异能倍率。
- 物理与异能各自的攻击次数。
- 群体攻击的分配规则。
- 攻击段数是否会因目标人数、击杀或特殊效果发生变化。
- 每段攻击能否分别触发暴击、状态和被动。

例如同为单次倍率100%，一次攻击的总倍率是100%，六次攻击的总倍率则是600%。攻击次数还会影响逐段触发、护盾消耗、反击、状态施加和击杀过程，不能只作为倍率乘数处理。

### 1. 完整倍率与分段倍率

《2D数值规范》中的倍率区间是 **完整技能总倍率**，已经把以下内容全部计算在内：

- 物理完整倍率。
- 异能完整倍率。
- 攻击人数。
- 每个目标承受的攻击段数。

CSV中的“分段伤害”才是实际分配到每个目标、每一段攻击上的倍率。

技能详情UI可能只显示取整后的单段百分比。将UI整数百分比重新乘以攻击人数和段数，可能得到比CSV完整倍率略低的结果。数值设计与分类以CSV中未取整的完整倍率为准，UI数字只用于玩家阅读，不能反推精确总倍率。

令攻击人数为 `T`，每个目标的伤害段数为 `N`：

```text
物理分段倍率 = 物理完整倍率 / (T × N)
异能分段倍率 = 异能完整倍率 / (T × N)

物理完整倍率 = 物理分段倍率 × T × N
异能完整倍率 = 异能分段倍率 × T × N

完整技能总倍率 = 物理完整倍率 + 异能完整倍率
```

因此，群体技能规范中的完整倍率按照设计攻击人数计算。实际场上目标不足时，如果技能不是分摊攻击，整项技能在该次战斗中的实际总伤害也会随命中人数减少。

仅记录设计状态下的完整倍率仍然不足以比较不同目标拓扑。以后还需要同时记录：

- `D1`：敌方有1个有效目标时，整项技能实际造成的完整总倍率。
- `D2`：敌方有2个有效目标时，整项技能实际造成的完整总倍率。
- `D3`：敌方有3个有效目标时，整项技能实际造成的完整总倍率。
- 单目标最高倍率：一次技能中，一名敌人可能实际承受的最高总倍率。

全体等额AOE会随着有效目标减少而降低整项总倍率；固定总量分摊则保持总攻击量不变，目标越少，单体承受倍率越高。两者不能因为三目标完整倍率相同就视为同一种技能。

最大生命比例伤害和处决不使用普通攻击倍率区间。它们需要按照单次生命比例、每轮触发次数、目标生命值和处决线单独评价。

快速选择顺序：

1. 先判断技能来源：普通技能、护援、连携或升华技。
2. 再判断目标方式：单体、全体AOE或固定总量分摊。
3. 功能多、频率高、条件容易满足时向区间下半段取值。
4. 只有费用、资源或条件真实限制使用时，才允许向上取值。
5. 高费用普通技能只有基础倍率也明显高于普通区间时，才进入11.4～16的普通爆发档。费用高本身不是越级依据。

### 8. 条件收益与特殊伤害的记录规则

基础倍率区间只管理CSV中的技能基础完整倍率。技能在释放前动态获得的增伤、暴击、费用变化和目标变化，需要另外记录实际结算结果。

#### 条件增伤

- 先按照技能来源、费用和目标方式选择基础区间。
- 分别记录未触发、常见触发和理论最高条件下的实际倍率。
- 增伤只作用于物理或异能时，只提高对应属性倍率，不能直接乘算物理与异能相加后的总倍率。
- 无上限或读取敌我属性差的效果，需要分开评价正常关卡、特殊编成和极端敌人。

#### 暴击强化

暴击率和暴击伤害不会改写CSV中的基础完整倍率。技能在伤害前获得暴击属性时，需要另外记录本次攻击的实际暴击率、暴击伤害和期望伤害。

#### 可变费用与超额支付

- 基础倍率仍然按照技能来源和目标方式选择。
- 分别记录每个实际费用档位的即时收益。
- 升华技被状态暂时降低至0费时仍然属于升华技，不改用低费普通技能区间。
- 同一状态同时提高伤害并降低费用时，两项收益必须合并评价，再与资源回落、失控或其他代价整体比较。

#### 额外攻击与逐段触发

- 使用攻击白值倍率的追击、反击和落雷，先计算一轮常见累计倍率，再反推单次倍率。
- 读取最大生命值的追击不使用普通攻击倍率换算。
- 每段触发的功能必须记录总层数上限。攻击段数可以加快有限层数的兑现速度，但不会凭空提高总收益。

#### 友伤与目标反转

友方伤害、目标反转和强制失控需要记录最常见损失与最坏损失。只有惩罚会在正常循环中真实发生、不能无成本取消，并且会影响后续行动或队伍生存时，才可以作为高倍率或低费用的实际代价。

## 十、单次攻击伤害结算

### 1. 总体顺序

当前蓝图中的伤害流程为：

1. 基础倍率计算。
2. 计算攻击方BUFF。
3. 计算暴击与暴击伤害。
4. 计算受击方BUFF。
5. 分别计算物理防御与异能防御。
6. 触发守备防御，由守备盾吸收伤害。

可以简写为：

```text
攻击白值 × 技能倍率
→ 攻击方BUFF
→ 暴击与暴击伤害
→ 受击方BUFF
→ 物理/异能防御
→ 守备盾
→ 剩余伤害进入生命值
```

### 2. 基础物理与异能伤害

一次攻击会同时读取物理倍率和异能倍率，不会只选择其中一种属性。令攻击白值为 `A`，本次单段物理倍率为 `Mp`，异能倍率为 `Mm`：

```text
基础物理伤害 P0 = A × Mp
基础异能伤害 M0 = A × Mm
```

物理和异能部分共用角色攻击白值，但之后会分别经过对应BUFF与防御结算。

如果技能拥有多次攻击，每一段都按照该段的物理倍率和异能倍率重新进行伤害流程，最后再累计各段实际造成的伤害。

### 3. 攻击方BUFF

基础倍率计算完成后，先应用攻击方自身的BUFF，得到调整后的物理伤害 `P1` 和异能伤害 `M1`。

物理增伤与异能增伤处于同一层级的两个平行乘区，分别修改对应属性伤害。最终伤害提高位于两种属性各自完成前置修正后的最后乘区。

不同BUFF可以采用直接加法或乘法，没有一条“所有同类BUFF统一相加或统一相乘”的全局规则，必须读取具体BUFF的实现。

一般不会额外设计攻击力提高BUFF；需要修改攻击力时，通常直接修改进入基础倍率计算的组合攻击白值。

### 4. 暴击

攻击方BUFF计算完成后，再计算本段是否暴击，并根据暴击伤害属性调整物理与异能伤害。

蓝图会同时把物理和异能伤害输入暴击计算函数，并输出暴击后的两部分伤害以及 `Is Critical` 结果。因此一次攻击段的物理与异能部分共享本次暴击判定。

令暴击前伤害为 `D`，换算后的暴击伤害比例为 `Cc`。本段暴击时：

```text
暴击后伤害 = D × (1 + Cc)
```

例如暴击伤害为58%时，暴击后的对应伤害为原值的1.58倍。物理与异能部分共享本段是否暴击的结果，但分别把自身伤害代入该公式。

### 5. 受击方BUFF

暴击结算以后，受击方先计算自身BUFF，再进入基础防御公式。

这一阶段可以承载受伤提高、伤害降低、属性易伤或其他由受击方状态产生的修正。先得到受击方BUFF调整后的伤害，再使用受击方自身物理防御和异能防御计算削减。

与攻击方BUFF相同，不同受击方BUFF可以各自采用加法或乘法，不能只根据名称假设统一叠加方式。

### 6. 物理与异能防御

受击方BUFF结算完成后，物理和异能伤害分别读取对应防御比例。

令进入防御步骤的物理伤害为 `P`，异能伤害为 `M`，受击方实际物理防御比例为 `Dp`，实际异能防御比例为 `Dm`：

```text
防御后物理伤害 Pafter = P × (1 - Dp)
防御后异能伤害 Mafter = M × (1 - Dm)

防御后总伤害 = Pafter + Mafter
```

因此，技能中的物理倍率和异能倍率都会形成实际伤害，只是分别受到物理防御和异能防御削减，最后再合并。

### 7. 守备盾与生命值

防御计算结束后，才触发受击方的守备防御。守备盾从防御后的伤害中进行抵扣，剩余部分最终进入生命值。

这意味着防御属性不仅减少生命值损失，也会降低每次攻击对守备盾造成的消耗。高防御与高守备值会在结算顺序上形成联动。

物理伤害只扣除物理盾，异能伤害只扣除异能盾。某一属性盾量不足以吸收本次对应伤害时，超过盾量的剩余伤害正常进入目标生命值。

守备状态按照每一段攻击实时更新。某一段打空对应盾量后，该盾立即破碎并退出相应守备；同一技能的后续攻击段不再读取已经破碎的盾，会正常削减目标生命值。

## 十一、速度、资源与守备刷新

### 1. 速度

Main与Sub速度直接相加，组合速度用于行动顺序和所有读取速度的机制。

加速和减速效果直接修改当前速度白值；BUFF结束时，再撤销该BUFF自己造成的数值变化。多个速度BUFF分别记录并恢复自己的修改量，因此正常情况下不会相互覆盖。

当前速度相同时存在已知排序缺陷：现有排序函数可能因完全相同的速度卡死。相同速度的正式先后手规则需要在修复排序函数时重新确定。

#### 当前角色速度锚点

角色基础速度不能只按照原作中“快或慢”的印象单独决定，还要检查该数值在现有角色池中的相对位置，以及角色自身的抢先行动、守备建立、减速和速度差机制。

| 角色 | 基础速度 | 当前速度定位 |
| --- | ---: | --- |
| 爱丽丝【UW】 | 520 | 当前低速、防守型角色参考 |
| 御坂美琴 | 720 | 主动型高速角色，但不占用速度专精档位 |
| 亚丝娜【SAO】 | 758 | 依靠抢先行动建立追击的速度专精参考 |
| 优纪【ALO】 | 800 | 绝剑高速参考 |
| 优纪【天使】 | 820 | 当前常规角色中的更高速度参考 |
| 辛克莱【准执柄者】 | 999 | 已有特殊高速度值，不作为常规高速角色的直接模板 |

新角色确定速度时，应先说明它需要在哪些现有角色之前或之后行动，再选择具体数值。速度不是独立的还原属性；如果角色不读取先后手、速度差或行动前置状态，就不应仅凭“原作动作很快”直接进入速度专精档位。

在同速排序缺陷修复以前，新角色基础速度还应主动避开已有角色的精确数值。不能为了整数整齐而大量使用相同速度。

#### 御坂美琴：720速度

御坂美琴的基础速度确定为 **720**。

这个数值高于爱丽丝【UW】的520，使御坂能够较早释放技能并建立反击守备，符合她主动、直接和不愿等待的战斗方式；同时低于亚丝娜【SAO】的758、优纪【ALO】的800和优纪【天使】的820，不会占用以速度作为核心特色的角色档位。

御坂的二技能每次命中永久降低目标30速度，最多降低200。以720为基准，现有速度锚点会形成以下跨档次数：

| 目标 | 初始速度 | 御坂需要施加的减速次数 | 减速后速度 |
| --- | ---: | ---: | ---: |
| 亚丝娜【SAO】 | 758 | 2次 | 698 |
| 优纪【ALO】 | 800 | 3次 | 710 |
| 优纪【天使】 | 820 | 4次 | 700 |
| 辛克莱【准执柄者】 | 999 | 达到200上限后仍无法反超 | 799 |

因此，720不仅表现御坂自身反应较快，也让永久减速产生清楚的行动顺序变化：面对一般高速角色，她能通过数次攻击夺走先手；面对特殊高速度角色，即使减满也不能无条件反超。减速由此保留长期收益，又不会把所有速度差异压平。

### 2. 技能点与升华点

| 资源 | 初始值 | 最大值 | 最小值 |
| --- | ---: | ---: | ---: |
| 技能点 | 0 | 20 | 0 |
| 升华点 | 0 | 20 | 0 |

我方全队共享一套技能点和升华点，敌方全队共享另一套，敌我资源彼此独立。

每次角色行动开始，当前行动方获得2点技能点。释放技能消耗对应技能点，并获得等量升华点。扣除技能点不能把资源降到0以下，超过20的资源也按照20处理。

### 3. 守备刷新

角色每次释放技能都会重新生成该技能对应的守备值，无论技能是正常释放还是被丢弃。新守备值会完全替换此前剩余守备值，不进行累加或补充。

角色跳过回合时没有释放技能，因此不会生成或刷新守备，原有剩余守备状态继续保留。

## 十二、反击守备与拼刀

### 1. 触发条件

反击守备在代码中使用 `PreformType == Attack` 表示。扫描攻击目标时：

- 无效目标会被跳过。
- 阵营筛选后，只检查本次允许参与的目标。
- `NotBreak` 为真的目标不能被打断，会跳过反击拼刀。
- 如果双方都处于反击守备，则开始拼刀。

### 2. 胜负判定

系统根据被攻击者基础抗性，决定本次拼刀比较物理守备值还是异能守备值。代码中的核心判定为：

```text
使用异能比较：自身异能守备值 > 对方异能守备值
使用物理比较：自身物理守备值 > 对方物理守备值
```

守备值更高的一方获胜。当前代码使用严格大于号，双方数值完全相等时的归属依赖调用方向，需要结合实际触发对象继续确认。

### 3. 反击倍率

反击伤害倍率读取胜者自身状态。令胜者当前生命为 `H`，生命上限为 `Hmax`，基础反击倍率为 `Rbase`：

```text
反击倍率 R = 1 - H / Hmax + Rbase
```

也可以理解为：

```text
反击倍率 = 胜者已损失生命比例 + 基础反击倍率
```

胜者生命越少，本次反击伤害和击飞力度越高。满生命时倍率等于基础反击倍率；损失50%生命时，在基础倍率上增加0.5。

如果允许负生命角色继续参与拼刀，已损失生命比例可能超过1，反击倍率也会继续提高。这一特殊边界需要结合负生命角色的可行动规则确认。

### 4. 反击伤害

反击伤害使用胜者的组合攻击白值：

```text
反击基础伤害 = 胜者组合攻击力 × 反击倍率
```

本次反击由 `DefAtkPhy` 决定属性：

- `DefAtkPhy = true`：全部作为物理伤害。
- `DefAtkPhy = false`：全部作为异能伤害。

反击伤害随后进入暴击计算，可以发生暴击。暴击计算完成后，`DefenseAttackTrigger` 会继续计算受击方BUFF和对应的物理或异能防御。

由于代码在触发反击伤害以前已经清空双方全部守备值并退出守备状态，本次反击伤害不会再被拼刀前遗留的守备盾吸收；经过受击方BUFF和防御削减后的伤害直接进入生命值。

### 5. 击飞与守备清空

```text
反击击飞力度 = 反击倍率 × 1500
```

拼刀结束后，无论胜负，双方都会：

- 物理守备值归零。
- 异能守备值归零。
- 闪避次数归零。
- 更新守备UI。
- 退出当前守备状态。

因此一次拼刀会完整清空双方守备，不会保留未使用的另一属性盾量或闪避次数。

## 十三、当前能够得出的结论

### 1. 品质差异主要决定养成起点和选择空间

高品质角色拥有更高的初始生命、攻击和次级属性，也拥有更多技能升级次数。品质不仅提高强度，还减少角色为了达到同一构筑目标所需的养成投入。

### 2. 初始次级属性与养成上限差距很大

即使S级角色初始拥有100暴击率原始值，实际暴击率也只有2%；初始200防御原始值对应8%。大部分暴击和防御能力预计来自后续养成，而不是品质基础值本身。

### 3. 防御上限的边际价值很高

防御从单人初始区间提高到单人上限9100时可以达到43.6%，Main与Sub合计达到18200时可以达到80%。防御在守备盾以前结算，因此生命、防御和守备之间会产生明显的复合生存收益。

### 4. 技能等级必须结合攻击次数评价

技能升级提高的是每次攻击倍率时，多段技能会把每一点单次倍率成长重复兑现。以后建立技能等级基准时，不能只比较截图中的倍率差值，必须先计算各等级总倍率。

### 5. 混合倍率必须拆分后再相加

技能的物理倍率和异能倍率都会参与同一次攻击。评价总倍率时不能先把两种倍率简单视为完全等价，因为两部分会分别受到敌人物理防御和异能防御影响。

同一个技能面对物理抗性、异能抗性或双防均衡的敌人时，实际价值可能不同。

### 6. 技能费用不能单独决定倍率档位

现有样本中，4费普通单体技能仍可能只处于6.4至9的普通输出区间，6费普通技能也可能停在9的区间上限。只有技能同时具备明显使用代价和越过普通区间的基础完整倍率，才应归入11.4至16的高费用普通爆发档。

### 7. 基础倍率与实际爆发必须分开保存

速度差增伤、SAN最终伤害、超额支付、形态暴击和种族特攻都可能在技能伤害前动态生效。CSV继续保存可审计的基础物理与异能倍率；角色数值测试另外保存常见条件和极端条件下的实际输出。否则动态角色会因为只看CSV显得偏弱，或因为只看理论上限显得失控。
