# 1 · 控件基类 `UDreamWidget`

## 它是什么

`UDreamWidget` 是 DreamGUI 里「几乎所有 UI 相关东西」的基类〔A-82〕。它是一个 `UObject`，不是 `UWidget`，也不是 Actor 或 ActorComponent。

这一句里三个否定比肯定更重要。控件带一个矩形、一个轴心和一组锚点，挂在树上，由画布合批画出来。整个过程背后**没有 `SWidget`** —— UMG 的控件、样式与绑定在这里都不适用，因为那些东西全都长在 Slate 上。

## 一个控件由哪几块拼起来

一个控件**自己什么都不画、也什么都不排**。它的每一项职责都交给挂在它身上的一个子对象〔C-26〕。这个结构是整个插件最需要先记住的一件事。

```text
UDreamWidget            矩形 + 轴心 + 锚点，挂在树上
├─ AnchorData          相对父级在哪、多大        （唯一必有的一个）
├─ Visual              画什么                    （至多一个；没有它就是纯容器）
├─ LayoutContainer     怎么排自己的孩子
├─ LayoutSelf          自己的尺寸规则
├─ PanelSlot           父级面板怎么放我
└─ Behaviours[]        逻辑（按钮、画布、导航……）
```

（这里用代码块而不是图：组件关系是一棵单层树，一张矩阵图不会比这段多说什么。）

属性面板把它们分成 12 个分类：`Transform`、`Render Transform`、`Perspective`、`DreamGUI-AnchorData`、`DreamGUI`、`Behavior`、`Interaction|Focus`、`Interaction`、`Localization`、`Accessibility`，加上 `Visual`/`LayoutContainer`/`LayoutSelf`/`PanelSlot` 四个独立分类〔A-83〕。

在 `.dui` 里这几样一眼能分开：节点类型是视觉或容器，`+ Class { }` 挂行为，`@slot` 写上层面板对它的安排〔C-26〕。

## 矩形：锚点、轴心与尺寸

`AnchorData` 是一个 `FDreamUIAnchorData`，五个字段，默认值是「锚在父级中心、100 × 100 的方块」〔C-28〕：

| 字段 | 含义 |
| --- | --- |
| `AnchorMin` / `AnchorMax` | 父级矩形里的两个归一化点。某个轴上两者**相等**，控件在这个轴上钉在一个点；**不等**，就在这个轴上拉伸 |
| `SizeDelta` | 钉在点上时是**尺寸**；拉伸时是**超出锚点跨度**的那部分，`0` 正好贴合，负值是内缩 |
| `AnchoredPosition` | 轴心相对锚点的偏移 |
| `Pivot` | 控件自己矩形里的归一化点，`(0, 0)` 是左下、`(1, 1)` 是右上 |

**坐标是 y 朝上的**：`Pivot`、`RenderTransformPivot`、`PerspectiveOrigin` 都以左下为原点，和 UMG 的左上原点不同。这一条是作者有意选的，参考页上写着「插件内部一致比和另一个引擎一致更重要」〔A-88〕。

那个 `RelativeLocation` 属性在属性面板上看得见，但**对 `.dui` 隐藏**。原因是它的 setter 会**反算锚点**，而 `.dui` 拼的正是 `AnchorData` —— 反射遍历如果也写它，同一个位置就被授权了两次〔A-84〕。所以 `.dui` 里只写 `AnchorData`。

尺寸模型是**盒子优先**：矩形是你写出来的，内容排在它里面，因此**文本可以溢出**。这是与 UMG「内容决定尺寸」的结构性差别，也是 `Margin`、`LineHeightPercentage`、`WrapTextAt` 和 Best Fit 在这里存在的原因〔C-29〕。不过盒子优先不等于没有内容尺寸：放上面板后，面板会问控件 `GetDesiredSize`，再把手排好的矩形写回它的 `AnchorData`。视觉回答这个问题时**负数表示弃权**（退回写出来的矩形），`0` 才是明确回答〔C-30〕。

## 画法与布局分家：渲染变换

控件有两条互不干扰的「位置」：布局决定它**在哪**，渲染变换决定它**画在哪**。

渲染变换有 5 个通道〔A-87〕：

| 通道 | 作用 |
| --- | --- |
| `RenderTranslation` | `FVector`，X 是**深度**、朝远离观察者；负 X 把控件拉向屏幕 |
| `RenderRotation` | `FRotator`，绕 `RenderTransformPivot` 转，单位度 |
| `RenderScale` | `FVector`，绕 `RenderTransformPivot` 缩放 |
| `RenderTransformPivot` | 归一化，`(0,0)` 左下；与布局用的 `AnchorData.Pivot` **互不相干** |
| `RenderShear` | `FVector2D`，单位度，作用于本控件与整棵子树 |

布局对渲染变换**一无所知**：兄弟不会挪，任何东西都不会写回 `AnchorData`〔C-31〕。这正是它与 `RelativeLocation` 的全部区别 —— 后者的 setter 会反算锚点并请父级重新布局，所以在面板里给它做动画永远不行，动画和布局只会轮流改它〔C-31〕。

第 5 个通道要单独说。`RenderShear` **不算进 `HasRenderTransform`**：另外三个会合成一个 `FTransform`，斜切过不去这趟，所以它单独存放、走矩阵路径。更要紧的是**命中测试不跟随它** —— 射线只在透视作用域内才切到矩阵，所以一个斜切的控件是按**未斜切的矩形**接收点击的。它也不能打关键帧，另外三个通道可以〔A-89〕。

旋转还有一个坑。`RelativeRotation` 是 `FQuat`，而 **Sequencer 没有 `FQuat` 属性轨**，所以它不能直接打关键帧；能打的是它的镜像 `RelativeRotationEuler`（`FRotator`）〔A-85〕。同样的道理，锚点几何有 6 个 `Animatable*` 镜像（宽、高、四条边）专供 Sequencer〔A-85〕。

`RenderLayer` 是个模式而不是通道，取值 `Auto` / `Always` / `Never`。渲染变换持续变化的控件会被画布做成**渲染层**（`UDreamUIRenderLayerTable`），层的变换在 **GPU 上**作用于它下面的所有东西〔A-87〕〔C-43〕。

**逐控件透视**由三个属性控制：`bPerspective`、`PerspectiveFieldOfView`（默认 60 度）、`PerspectiveOrigin`（归一化，左下原点）。眼距不是单独设的，而是按同一公式从这个视场角对**控件自己的宽度**推出来的，`GetPerspectiveDistance` 给出推算结果〔A-88〕。形状同 CSS 的 `perspective`，嵌套是**嵌套**不是覆盖。

## 树怎么搭：四个动词

四个动词的语义差别是刻意做出来的，混用会漏资源〔A-90〕：

| 动词 | 做什么 | 什么时候用 |
| --- | --- | --- |
| `AddChild` | 挂上去，返回孩子的 `UDreamPanelSlot*` | 正常添加。UMG 需要八个带类型的变体（每个面板一种槽），这里只有一种槽，所以一个动词返回它，可以直接在结果上设 padding |
| `RemoveChild` | 摘下来但**留着**：仍注册、子树完整、回到「刚创建」状态 | **做对象池就用这个** |
| `DestroyChild` | 拆掉孩子及其整棵子树 | 确定不再用了；之后 `IsValid` 为假 |
| `DestroyAllChildren` | 拆掉每个孩子及其子树 | ⚠️ UMG 的 `ClearChildren` 只分离并交给 GC，在这里会**留下没人持有的、活着的已注册控件** |

`AddChild` 可能返回 null，而这**不是失败**：控件可以完全没有布局容器也收孩子，而 DreamGUI 的 flex box 与 grid **不给槽**。「能收孩子」与「有槽」是两件事，`HasPanelSlots` 就是回答这个问题的查询〔A-91〕。

按名查找有单值与数组两个版本（`FindChildByDisplayName` / `FindChildArrayByDisplayName`），**大小写敏感**，支持**嵌套路径**，例如 `"Content/ListItem/NameLabel"`〔A-92〕。

## 可见、可交互、可命中：三层开关

这三件事被拆成互不代管的一组开关，混用是最常见的一类困惑〔C-35〕：

| 层 | 开关 | 管什么 |
| --- | --- | --- |
| 布局与绘制 | `Visibility`（5 值） | `Visible` / `Hidden`（占位但不画）/ `Collapsed`（不占位）/ `HitTestInvisible` / `SelfHitTestInvisible` |
| 生命周期 | `bWidgetActive` | 不激活就不可见、不占布局、不可交互、不可命中，行为收到 `OnDisable` |
| 输入许可 | `bIsEnabled`、`Interactable`、`Raycastable` | 整棵子树是否收输入、是否可被射线命中 |

`Shown` 是 `Visibility` 的是 / 否形式：`true` 是 `Visible`，`false` 是 `Collapsed`。它**自己不存任何东西** —— 读它就是读 `Visibility`（除 `Collapsed` 之外都算 shown），写它就是写 `Visibility`；面板上那个字段只是反射需要一个带 getter/setter 的槽位〔A-86〕。它不会改掉「隐藏」或「不可命中」：一个 `Hidden` 的控件被设成 shown 以后还是 `Hidden`〔C-35〕。

`bIsEnabled` 被 **AND 进三值的 `Interactable` 级联**，输入、导航与每个控件的禁用外观读的都是 `GetInteractableInHierarchy` 这一个答案。由此得出一条反直觉的结论：**被禁用的祖先压过钉住 `Interactable=Enabled` 的后代**〔A-95〕。

透明与染色也是树状的：`RenderOpacity` 沿树**向下相乘**，`GetFinalRenderOpacity` 取乘完的值；`SetContentTint` 只染**后代**的视觉、**从不染自己**，在线性空间与每个祖先的相乘后进入 `GetFinalColor`，白色不改变任何东西〔A-96〕。剪裁是 `Clipping` 四值，另有 `ClippingCornerRadius` 与 `ClippingMargin`〔C-35〕。

**级别查询成对存在，而且有一处与 UMG 不同**：`IsVisible` **把层级折叠进去了**，UMG 的只问控件自己；`IsHovered` 的答案是「指针在本控件**或它里面任何东西**上」，悬停会传给祖先 —— 这正是按钮在指针压到它的标签上时仍然 hover 的原因〔A-94〕。

## 焦点、Tab 与导航边界

焦点与 Tab 是四个属性加两个入口：`bIsFocusable`、`bIsTabStop`（关掉就等于浏览器的 `tabindex="-1"`，只留给方向键、手柄、指针和代码）、`TabIndex`（**只与兄弟比较**，小的在前）、`TabNavigation`；入口 `SetKeyboardFocus`（在拥有玩家的 event system 上取焦点，取不到返回 false）与 `SetUserFocus`（指定玩家）。关掉 `bIsFocusable` 会**同时交出当前持有的焦点**〔A-93〕。

导航边界是 `bRestrictNavigationArea` 与 `NavigationBoundaryRule`，后者**只在自身就是受限区域的控件上被读**，`Stop` 保持既有 prefab 的行为〔A-97〕。

`UDreamWidget` 只暴露 **3 个事件**：`OnVisibilityChanged`、`OnFocusReceived`、`OnFocusLost`。后两个是**公开**的，与 UMG 一致 —— 蓝图能绑的委托 C++ 也应该能绑；而且一个控件可以把它某个部件的焦点**代自己转发**出来〔A-97〕。

## 与 UMG 的对照

参考页末尾把 `UWidget` 的**逐个面向成员**列成三态：*adopt*（同名同义）、*map*（换了名字或换了类型）、*reject*（**故意缺席并给出理由**）〔A-98〕。挑几处对写代码最有影响的：

| UMG | 这里 | 为什么 |
| --- | --- | --- |
| `Slot` | `PanelSlot` | 只有一种槽类型，所以没有东西需要转型 |
| `ToolTipWidget` | `ToolTipWidgetClass` | 给的是**类**不是实例：气泡显示时才实例化、消失时销毁，避免为几秒的气泡长期保活 |
| `RenderTransform` | 拆成 4 + 1 个通道 | 它镜像的那套变换本来就是 `FVector`/`FQuat`/`FVector`，所以是三维的，不是 `FWidgetTransform` |
| `SetRenderScale` | 同 | 收 `FVector` 而不是 `FVector2D`：这里的控件是三维的，世界空间画布也存在 |
| `SetToolTip` | `SetToolTipWidgetClass` | 按类而不是按实例 |
| `GetCachedGeometry` / `GetTickSpaceGeometry` / `GetPaintSpaceGeometry` | **并成一个** `GetWidgetGeometry` | DreamGUI **排列与绘制在同一个 pass 里**，tick space 和 paint space 不可能不一致 |
| `bIsVolatile` / `ForceVolatile` | **拒绝** | volatility 是 Slate 失效面板的概念（"别缓存这个控件的绘制元素"）；这里按自己的脏标记重建绘制调用，**没有缓存元素表可退出** |
| `bOverrideAccessibleDefaults` / `bCanChildrenBeAccessible` | **拒绝** | 这里没有 Slate 无障碍层可以取默认值，也不建无障碍控件树 |

## 它换来了什么

设计取舍要两面看。下面这些是参考页与语言手册里**写明了理由**的改动 —— 每一行都能翻回出处，不是我的评价。

| 改了什么 | 换来了什么 |
| --- | --- |
| 控件是 `UObject` 树，不是 Slate 的保留模式 | UI 能立在关卡里、受光或被射线打中；屏幕空间与世界空间两种情况下命中测试都对〔C-25〕 |
| 一棵树就是一个类 | 界面能像类一样继承与嵌套，还能给宿主留具名插槽让别人填内容〔A-01〕 |
| **排列与绘制在同一个 pass 里** | tick space 与 paint space 不可能不一致 —— 这就是三个几何查询能并成一个的原因；画布也才能只遍历变化了的控件、原地修补分段〔A-98〕〔C-42〕 |
| 面板只有**一种**槽类型 | `AddChild` 一个动词、一种返回类型就够；UMG 要八个带类型的变体，每个面板一种〔A-90〕 |
| 渲染变换与布局分家 | 移动、缩放、旋转、透视可以每帧动画而不触发任何重排；持续变化的控件还能被抬成在 GPU 上移动的渲染层〔C-31〕〔A-87〕 |
| 逐控件透视是一等属性 | 一张卡片绕竖轴翻过来是平常操作，不用为它专门搭一个世界空间组件〔C-34〕〔A-88〕 |
| 可见性、生命周期、输入许可是**三组正交开关** | 能表达 UMG 表达不了的状态：占位但不画、活着但不跑行为、看得见但点不到〔C-35〕〔A-86〕 |
| `Shown` 只是 `Visibility` 的布尔写法，自己不存状态 | 只有一个真相源，不会出现「`Shown` 说他开着、`Visibility` 说他折叠了」〔A-86〕 |
| 斜切单独走矩阵路径、不算进 `HasRenderTransform` | 另外三个通道能合成一个 `FTransform` 走快路，不必为斜切让所有控件付代价〔A-89〕 |
| 旋转用 `RelativeRotationEuler` 当 Sequencer 的驱动面 | 用 `FRotator` 换取「能在 Sequencer 里打关键帧」 —— `FQuat` 没有属性轨〔A-85〕 |

⚠️ **这些「好处」取决于你从哪来。** 从 UMG 过来的人，第一感受大概是「少了 Slate 生态」；从 Unity uGUI 过来的人，第一感受更可能是「终于是盒子优先、锚点 + 轴心了」。插件自己承认这个形状是 **uGUI 的形状，不是 Slate 的**〔C-25〕。所以「它好不好」没有统一答案，看你拿它做什么 —— **世界空间 UI 是它最没有替代品的地方**。

## 什么时候它不好用

- **用不上 Slate 的生态**。没有 `SWidget` 就意味 UMG 的控件、样式、绑定全不适用，第三方 Slate 控件也不能挂进来。这是选型前就要接受的一笔账〔C-25〕。
- **文本会溢出**。盒子优先是结构性的，不是配置项；要靠 `WrapTextAt`、Best Fit、`Margin` 这些去管〔C-29〕。
- **斜切的控件点不准**。`RenderShear` 的命中测试按未斜切的矩形走，只有透视作用域里射线才切到矩阵〔A-89〕。
- **在面板里别动画 `RelativeLocation`**，也**别指望 `RelativeRotation` 打关键帧**。前者会被父级重排覆盖，后者没有属性轨；要动就用渲染变换的渐变版本与 `RelativeRotationEuler`〔C-31〕〔A-85〕。
- **`bIsEnabled` 压得住 `Interactable`**。想只禁一个后代而不动祖先，得先确认祖先没被禁用〔A-95〕。
- **它本身不是「一个控件类」**。做界面时你继承的是 `UDreamUserWidget`（`UDreamWidget` 的子类），`UDreamWidget` 更多是「控件在这个框架里能做什么」的集合。

## 怎么用

`.dui` 里最小组装单元就是一个 `Widget` 节点 —— 它没有视觉，是个纯容器：

```text
class /Game/UI/WBP_Hello

Widget Root {
    AnchorData.AnchorMin = (0, 0)
    AnchorData.AnchorMax = (1, 1)
    AnchorData.SizeDelta = (0, 0)
    + Overlay {}

    Widget Card {
        AnchorData.AnchorMin = (0.5, 0.5)
        AnchorData.AnchorMax = (0.5, 0.5)
        AnchorData.SizeDelta = (420, 220)

        Text Greeting { Text = "Hello, DreamGUI" }
    }
}
```

`Root` 锚在四角、不留边，所以它铺满被加进去的东西；`Card` 锚在父级正中一个点上，`SizeDelta` 就是它的尺寸。〔C-28〕

C++ 里创建与挂载：

```cpp
// 建出来：尚不可见、行为不跑，管理器持有它免得被回收
UDreamWidget* Widget = UDreamUIBPLibrary::ConstructWidget(this, TEXT("Card"), UDreamWidget::StaticClass());

// 挂上去，顺手拿到槽去设 padding
UDreamPanelSlot* Slot = Parent->AddChild(Widget, -1);

// 对象池：摘下来但留着，回到「刚创建」状态
Parent->RemoveChild(Widget);
```

`AddChild` 返回的槽是 `UDreamPanelSlot*`，全局面板只有这一种，不必转型〔A-90〕。想按名找回子节点用 `FindChildByDisplayName(TEXT("Content/ListItem/NameLabel"))`〔A-92〕。

## 出问题先查这几处

| 现象 | 先看 |
| --- | --- |
| 写了位置但 `.dui` 里没有它 | 位置只认 `AnchorData`；`RelativeLocation` 对 `.dui` 隐藏〔A-84〕 |
| 数据改了动画不动 | 检查改的是 `RelativeRotation`（不可关键帧）还是 `RelativeRotationEuler`〔A-85〕 |
| 动画一动就被弹回去 | 在面板里给 `RelativeLocation` 做了动画 —— 换 `Render*To` 系列〔C-31〕 |
| 设置 `Shown` 之后还是看不见 | `Shown` 不改掉 `Hidden` / 不可命中，先看 `Visibility` 原值〔C-35〕 |
| 父节点禁用后子节点还亮着 | `bIsEnabled` 是 AND 进级联的，看 `GetInteractableInHierarchy`〔A-95〕 |
| 斜切后点不中 | 命中测试不跟随 `RenderShear`〔A-89〕 |
| `AddChild` 返回 null | 该控件没有布局容器（或容器是 flex box / grid，它们不给槽）；`HasPanelSlots` 可查〔A-91〕 |
| 换父节点后位置乱 | `RemoveChild` 保活但不保位；要保世界位置用 `SetParent(..., bKeepWorldPosition=true, ...)`〔A-90〕 |

# 2 · 锚点数据 `FDreamUIAnchorData`

## 它是什么

`FDreamUIAnchorData` 是控件回答「我在父级里哪、多大」的**唯一真相源**。它是一个 `USTRUCT(BlueprintType)`，5 个字段全部 `EditAnywhere, BlueprintReadWrite`，分类都是 `DreamGUI`〔A-99〕。

它的头文件只有 26 行，文件头第一行还是 `Copyright 2019-Present Lex Liu` —— 这是 LGUI 血缘在源码层留下的最直接的一处痕迹〔A-99〕。

## 五个字段与默认值

字段的声明顺序就是下面这个顺序，`Pivot` 在最前〔A-99〕：

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `Pivot` | `FVector2D` | `(0.5, 0.5)` | 控件自己矩形里的归一化点，`(0, 0)` 是左下、`(1, 1)` 是右上 |
| `AnchorMin` | `FVector2D` | `(0.5, 0.5)` | 父级矩形里的第一个归一化点 |
| `AnchorMax` | `FVector2D` | `(0.5, 0.5)` | 父级矩形里的第二个归一化点 |
| `AnchoredPosition` | `FVector2D` | `(0, 0)` | **轴心**相对锚点的偏移 |
| `SizeDelta` | `FVector2D` | `(100, 100)` | 钉在点上时是**尺寸**；拉伸时是**超出锚点跨度**的那部分 |

默认这一组读起来就是「锚在父级中心的一个 100 × 100 方块」〔C-28〕。一个全新的控件不需要配任何东西就已经在父级正中。

## 每条轴各自决定「钉点」还是「拉伸」

结构体自己带了两个谓词来问这件事〔A-99〕：

```cpp
bool IsHorizontalStretched() const { return AnchorMin.X != AnchorMax.X; }
bool IsVerticalStretched()   const { return AnchorMin.Y != AnchorMax.Y; }
```

于是每条轴只有两种状态：

- **`AnchorMin` 与 `AnchorMax` 在该轴上相等** → 这一轴**钉在一个点**，`SizeDelta` 是尺寸，`AnchoredPosition` 是轴心离那个点的偏移。
- **不相等** → 这一轴**拉伸**，`SizeDelta` 变成「超出锚点跨度」的部分：`0` 正好贴合，负值是内缩。

**两条轴互不影响**，所以「横向拉伸、纵向钉点」这种混合是常态〔C-28〕。铺满父级就是把四个值都推到两端：`AnchorMin = (0, 0)`、`AnchorMax = (1, 1)`、`SizeDelta = (0, 0)`〔C-28〕。

## 坐标是 y 朝上的

`Pivot` 以**左下**为原点，而不是 UMG 的左上。同一套原点还用在 `RenderTransformPivot` 与 `PerspectiveOrigin` 上 —— 三处一致是刻意选的，在线文档里的原话是「插件内部一致比和另一个引擎一致更重要」〔C-27〕〔A-88〕。

## 运行时怎么改

三族 API，都是从控件上改，不是改结构体副本〔A-99〕：

| 族 | 成员 |
| --- | --- |
| **setter** | `SetAnchorData`、`SetAnchorMin`、`SetAnchorMax`、`SetAnchoredPosition`、`SetAnchoredPositionAndSizeDelta`、`SetSizeDelta`、`SetPivot`、`SetAnchorOffset`，以及四条边 `SetAnchorOffsetLeft` / `Right` / `Top` / `Bottom`，还有按结果说话的 `SetWidth` / `SetHeight` |
| **getter** | `GetAnchorData`、`GetAnchorMin`、`GetAnchorMax`、`GetAnchoredPosition`、`GetHorizontalAnchoredPosition`、`GetVerticalAnchoredPosition`、`GetAnchorOffset` 与它的四条边版本、`GetSizeDelta`、`GetPivot` |
| **渐变** | `AnchoredPositionTo`、`HorizontalAnchoredPositionTo`、`VerticalAnchoredPositionTo`、`SizeDeltaTo`、`WidthTo`、`HeightTo`，都返回一个 `UDreamTweener*` |

⚠️ 四条边的 setter 有一条前提，参考页上只有一句话：「This function only valid if UIItem have parent」〔A-99〕。

另有 6 个 `Animatable*` 镜像（宽、高、四条边）挂在同一个 `DreamGUI-AnchorData` 分类下，**只读**，是给 Sequencer 打关键帧用的，不是让你当数据源读的〔A-85〕。

## 与 UMG 的对照

| 面 | UMG | 这里 |
| --- | --- | --- |
| 原点 | 左上 | **左下**，且 `Pivot` / `RenderTransformPivot` / `PerspectiveOrigin` 三处统一〔C-27〕 |
| 位置属性的写法 | 有一个 `RelativeLocation` 可写 | **对 `.dui` 隐藏**：它的 setter 会反算锚点，而 `AnchorData` 才是 `.dui` 拼的东西，两个都写等于把同一个位置授权两次〔A-84〕 |
| 「四边距离」这种按结果的写法 | 要靠 Offsets 自己算 | 有 `SetAnchorOffset` 与四条边 setter 直接给〔A-99〕 |
| 做动画 | 位置动画会牵动布局 | 锚点每个字段都有渐变版本，但**在面板里动位置应该用渲染变换的 `Render*To`** —— 锚点一动父级就要重排〔C-31〕〔C-81〕 |

## 什么时候它不好用

- **`SizeDelta` 不是「尺寸」这一个意思。** 拉伸轴上它是「超出跨度的那部分」。想读尺寸得先问 `IsHorizontalStretched` / `IsVerticalStretched`，或直接用 `GetWidth` / `GetHeight` 这类按结果取值的入口。
- **别写 `RelativeLocation`。** 它在 `.dui` 里是隐藏的，而且是反算出来的〔A-84〕。
- **四条边的 setter 需要父级。** 没有父级时它们无效〔A-99〕。
- **在面板里别拿锚点做动画。** 改锚点会请父级重新布局，动画和布局只会轮流改它；要在面板里动位置就用渲染变换那一族〔C-31〕。
- **`Animatable*` 只读。** 那是 Sequencer 的驱动面，不是第二份真相源〔A-85〕。
- **它不是「内容尺寸」的答案。** 盒子优先的前提下，视觉回答 `GetDesiredSize` 时**负数表示弃权**，`0` 才是明确回答；锚点数据是排完之后的落点，不是排之前的意愿〔C-30〕。

## 怎么用

`.dui` 里只写 `AnchorData` 的点路径：

```text
Widget Root {
    // 铺满父级：四个值推到两端，SizeDelta 归零
    AnchorData.AnchorMin = (0, 0)
    AnchorData.AnchorMax = (1, 1)
    AnchorData.SizeDelta = (0, 0)
}

Widget Card {
    // 锚在父级正中一个点上：SizeDelta 就是尺寸
    AnchorData.AnchorMin = (0.5, 0.5)
    AnchorData.AnchorMax = (0.5, 0.5)
    AnchorData.SizeDelta = (420, 220)
    AnchorData.AnchoredPosition = (0, 40)
}
```

C++ 里改锚点：

```cpp
// 钉点：宽高直接给
Widget->SetSizeDelta(FVector2D(420, 220));
Widget->SetAnchoredPosition(FVector2D(0, 40));

// 拉伸：四条边的距离，相当于 CSS 的 inset
Widget->SetAnchorOffset(FMargin(24, 16, 24, 16));

// 想动得顺一点就用渐变版本，它返回一个 UDreamTweener
Widget->SizeDeltaTo(FVector2D(420, 260), 0.2f, 0.0f, EDreamTweenEase::OutQuad);
```

## 出问题先查这几处

| 现象 | 先看 |
| --- | --- |
| 改了 `SizeDelta` 却没变大小 | 那一轴是**拉伸**的 —— 此时它是「超出跨度」而不是尺寸；改用 `SetAnchorOffset` / `SetWidth`〔A-99〕 |
| 控件被拉扁或拉到负尺寸 | `AnchorMin` / `AnchorMax` 只改了其中一个；两个都推到位才能铺满〔C-28〕 |
| `.dui` 里写了位置但没生效 | 位置只认 `AnchorData`；`RelativeLocation` 对 `.dui` 隐藏〔A-84〕 |
| 四条边的 setter 没反应 | 该控件还没有父级〔A-99〕 |
| 动画一跑就被弹回去 | 在面板里给锚点做了动画，被父级重排覆盖；换 `Render*To`〔C-31〕 |
| 上下位置反了 | 原点在**左下**，与 UMG 相反〔C-27〕 |

## 还没核实的

参考页把控件上的 `AnchorData` 属性描述为「contains rect transform and color」，但这个结构体的 **5 个字段里没有颜色**〔A-99〕。疑为一句陈旧描述（早期版本可能有过颜色），**未核实**，写别的条目时别照抄这句话。

# 3 · 控件的子对象：视觉 / 布局容器 / 自身布局 / 面板槽

> 本条**合并**了功能总清单的 **#3 视觉槽**、**#4 布局容器槽**、**#5 自身布局槽**、**#6–#8** 三个自身布局变体，以及 **#9 面板槽**。它们各自只有几百字，拆开是七条浅条目，合起来才够一条完整的「我画什么 / 怎么排孩子 / 自己多大 / 父级怎么放我」。

## 每一项职责都交给一个子对象

控件**自己什么都不画、也什么都不排**〔C-26〕。「画什么」「怎么排孩子」「自己多大」「父级怎么放我」「有什么逻辑」分别由五个不同的子对象回答：

| 子对象 | 回答的问题 | 每个控件几个 |
| --- | --- | --- |
| `Visual` | 我画什么 | **至多一个**〔C-26〕 |
| `LayoutContainer` | 我怎么排孩子 | 可以没有 |
| `LayoutSelf` | 我自己多大 | 可以没有 |
| `PanelSlot` | 父级怎么放我 | **一种槽类，挂在孩子身上**〔B-01〕 |
| 行为数组 | 我有什么逻辑 | 可以有多个 |

前四个下面都讲。

## 视觉 `Visual`：19 个标签，三条绘制路径

视觉（`UDreamVisual`）共有三个属性：`Color`（sRGB，可以在 Sequencer 里打关键帧）、`bRaycastTarget`、`RaycastType`〔C-96〕。最后一个是「用**什么几何**去命中」，取值 `Rect` / `Mesh` / `VisiblePixel` / `Custom`；它和控件上的 `Raycastable` 三态不是一回事，后者管「**能不能**被命中」〔C-96〕〔C-35〕。

按怎么画出屏幕分成三类（`EDreamVisualType`）〔C-36〕：

- **`BatchMesh`** —— 由画布合批，**绝大多数**视觉都是这一类。
- **`DirectMesh`** —— 直接写自己的网格段，**每个都是一个 draw call**；用于顶点量大、变化频繁的内容，比如静态网格。
- **`PostProcess`** —— 读**写屏幕**的效果。

| `.dui` 标签 | 说明 |
| --- | --- |
| `Text` | 文本 |
| `Image` | 图片 brush |
| `RectBlock` | 程序化矩形块：圆角、主体、边框、内外阴影，主体与边框可带渐变 |
| `Sprite` / `Texture` | 图集精灵 / 整张纹理 |
| `Empty` | 不画任何东西，但**能被射线命中** |
| `UMGWidget` | 把一个 `UUserWidget` 画进渲染目标，再当 DreamGUI 几何体画 |
| `PostProcessRenderElement` / `PostProcessRenderElementText` | 后处理渲染元素 |
| `Ring` / `Polygon` / `PolygonLine` | 环、多边形、多边形描边 |
| `Line2DRaw` / `Line2DChildren` | 2D 线：给定点 / 以孩子为点 |
| `StaticMesh` | 静态网格，自成一个 draw call |
| `BackgroundBlur` / `BackgroundPixelate` / `PixelSort` | 屏幕效果：模糊 / 像素化 / 像素排序 |
| `CanvasRenderTargetPreviewer` | 显示一个渲染目标画布的内容 |

一共 **19 个**〔A-42〕。其中环、多边形、2D 线、静态网格、屏幕效果与 RT 预览这一族在 **`DreamGUIExtensions`** 模块，其余在核心模块〔C-37〕。

⚠️ 官方 wiki 的视觉表**只列了 16 行**〔C-37〕，漏掉 `UMGWidget`、`PostProcessRenderElement`、`PostProcessRenderElementText`。**以源码的 19 个为准**〔A-42〕。

**没有视觉的控件就是一个矩形** —— `.dui` 里的 `Widget` 就是纯容器〔C-26〕〔C-96〕。

## 布局容器 `LayoutContainer`：15 个

| 类 | 说明 |
| --- | --- |
| `UDreamLayoutContainerBorder` | 一个面、一圈内边距、一个放内容的洞 |
| `UDreamLayoutContainerCanvasPanel` | 自由摆放 |
| `UDreamLayoutContainerGridPanel` | 网格 |
| `UDreamLayoutContainerHorizontalBox` | 横排 |
| `UDreamLayoutContainerMenuAnchor` | 菜单从哪弹出 |
| `UDreamLayoutContainerOverlay` | 子节点叠着排 |
| `UDreamLayoutContainerSafeZone` | 安全区 |
| `UDreamLayoutContainerScaleBox` | 缩放盒 |
| `UDreamLayoutContainerScrollBox` | 滚动 |
| `UDreamLayoutContainerSizeBox` | 固定尺寸 |
| `UDreamLayoutContainerStackBox` | 栈 |
| `UDreamLayoutContainerUniformGridPanel` | 等分网格 |
| `UDreamLayoutContainerVerticalBox` | 竖排 |
| `UDreamLayoutContainerWidgetSwitcher` | 页面切换 |
| `UDreamLayoutContainerWrapBox` | 自动换行 |

以上 15 个容器都在核心模块 `DreamGUI` 里〔A-08〕〔C-46〕。

布局引擎是**按 Blink 和 Yoga 的思路重建**的，可核的三条特性是：测量是 `const` 的、片段不可变、失效**带原因**〔C-45〕。所有面板**只有一种槽类型** `UDreamPanelSlot`，不必转型〔C-47〕。

## 面板槽 `PanelSlot`：一个槽类替代 UMG 的一整族

**它挂在孩子身上，不是挂在父面板上。** 参考页的自述是「UMG-style per-child layout data **owned by the child widget**」，而且它本身继承 `UDreamWidgetSubObjectBehaviour` —— 也就是说**槽自己就是个行为组件**〔B-01〕。UMG 里槽属于父面板，所以每个面板各有一种槽类；这里只有**一种**。

17 个属性，全在 `Slot` 分类下，全部可在详情面板编辑并有对应的 `Set*` 蓝图函数〔B-02〕：

| 属性 | 管什么 |
| --- | --- |
| `Padding` | 内边距 |
| `HorizontalAlignment` / `VerticalAlignment` | 在父级给的矩形里怎么对齐 |
| `SizeRule` + `FillWeight` | UMG 的 `FSlateChildSize` 拆成两个：规则与值〔B-08〕 |
| `Row` / `Column` / `RowSpan` / `ColumnSpan` | 网格坐标 |
| `ZOrder` | 兄弟之间的绘制顺序（见下，多数面板忽略它） |
| `bAutoSize` | 自主尺寸 |
| `MinDesiredSize` / `MaxDesiredSize` | 逐轴作用在「这个孩子量出来的尺寸」上的**地板与天花板**，**零表示没意见**〔B-04〕 |
| `Nudge` | 一个固定偏移，最后加在面板决定的位置上（见下）〔B-05〕 |
| `bFillEmptySpace` / `FillSpanWhenLessThan` / `bForceNewLine` | **只有 WrapBox 读**，对准 UMG 的 `UWrapBoxSlot`〔B-03〕 |

### 四个属性是面板专用的

- **`bFillEmptySpace` / `FillSpanWhenLessThan` / `bForceNewLine` 只有 WrapBox 读。** 其中 `bFillEmptySpace` 还有一句补充：同一行里**别的**孩子问它，它什么都不做〔B-03〕。
- **`ZOrder` 只在三个地方生效**：Overlay 与 GridPanel **恒定消费**，CanvasPanel 在 `SortChildrenByZOrder` 打开时消费；**其余面板严格按兄弟顺序排列，忽略这个值**〔B-03〕。

### `Nudge` 有个坐标系陷阱

它是个固定偏移，坐标系是**面板的内容空间：x 右、y 下**（和 `Padding` 一个方向感）〔B-05〕。

⚠️ 这和插件其它地方的 **y 朝上**（`SetPosition` 的 y、`Pivot` 的原点）是**反的** —— 两套坐标系各管一段，混着读会把上下弄反〔B-10〕。

它在 `UDreamPanelLayoutBase::ApplyChildRect` 里应用，所以**每个面板都遵守它**，不只是网格；而且它**对测量不可见**〔B-05〕。

### 一个槽类替代 17 个 UMG 槽类，代价写在名字上

该页的 UMG 对照表覆盖 **17 个 UMG 槽类**（从 `UBackgroundBlurSlot` 到 `UWrapBoxSlot`）〔B-07〕。代价很具体：UMG 的 `UHorizontalBoxSlot::SetSize(FSlateChildSize)` **不能**在这里也叫 `SetSize` —— 裸名被画布的「矩形族」占了，盒子的那个拆成 `SetSizeRule` + `SetFillWeight`〔B-07〕。

四处关键的「宁可换名字、也不存第二份数据」〔B-08〕：

| UMG | 这里 | 为什么 |
| --- | --- | --- |
| `UCanvasPanelSlot::LayoutData` | `UDreamWidget::AnchorData` | 画布的孩子把矩形**说在控件自己身上**，槽读写那份数据，不存第二份 |
| `UGridSlot::Layer` | `ZOrder` | 网格的层与槽的 z 序是**同一件事**；`GetLayer` / `SetLayer` 保留 UMG 的名字但转发过去，不再存第二个数 |
| `UHorizontalBoxSlot::Size` | `SizeRule` + `FillWeight` | 一个规则加一个值，拆成两个 |
| `UPanelSlot::GetContent` | `GetWidget` | 槽属于它所摆放的那个控件，所以它的内容就是那个控件 |

SafeZone 的两个成员**留在面板上**而不是槽上（`bIsTitleSafe` → `UDreamLayoutContainerSafeZone::bUsePlatformSafeZone`、`SafeAreaScale`）—— 因为安全区只收一个孩子，「这个槽要求平台安全区」与「这个面板应用它」是同一个开关〔B-09〕。

### 三处「名字沿用、读法不同」

- **`SetPosition` 的 y 朝上**，而 UMG 是朝下〔B-10〕。
- **`SetSize` 写的是 `SizeDelta`**：点锚时是解出来的尺寸，**拉伸时是超出锚点跨度的那部分**〔B-10〕。
- **`SetOffsets` 在点锚时不照 UMG 那样把 `Right` / `Bottom` 当尺寸用** —— 那个读法是 `GetSize` / `SetSize`〔B-10〕。

### 失效原因分两档

`NotifySlotChanged(EDreamLayoutInvalidation Reason)` 的 `Reason` **默认是 `Measure`**；但 `Alignment`、`SizeRule`、`FillWeight`、`ZOrder` 传 **`Arrange`** —— 理由是它们**逐个查过**，都不出现在任何面板的 `MeasureLayout` 里，所以移动不了首选尺寸，只能改变这个槽的控件最终落在父级内的位置；而 `Padding`、网格坐标与 `bAutoSize` **确实出现在那里**，保持默认〔B-06〕。

### 什么时候它不好用

- **`Nudge` 的 y 朝下**，别按 y 朝上算〔B-05〕。
- **三个 WrapBox 专有属性在别的面板上什么都不做**〔B-03〕。
- **`ZOrder` 在多数面板上被忽略** —— 想让兄弟换次序，看那个面板认不认它〔B-03〕。
- **`SetSize` / `SetOffsets` 在点锚与拉伸两种轴上是两套读法**，混用会算出错的尺寸〔B-10〕。

## 三条共同的规矩

1. **视觉至多一个，其余可以没有。** 没有视觉的控件是个矩形；容器与自身布局都可以缺〔C-26〕。
2. **槽只有一种，但「能收孩子」≠「有槽」。** 控件可以完全没有布局容器也收孩子，而柔性盒与网格**不给槽** —— 所以 `AddChild` 返回 null 是正常情况，不是失败；`HasPanelSlots` 就是回答这个问题的查询〔C-47〕〔A-91〕。
3. **尺寸是谈出来的。** 父容器会问孩子 `GetDesiredSize`，孩子可以用**负数弃权**（退回自己写出来的矩形），`0` 才是明确回答〔C-30〕。

## 什么时候它们不好用

- **程序化形状会「弃权」。** 环、多边形、多边形描边没有「想要多大」的答案 —— 顶点直接从给定矩形推出，所以它们**跟着你写出来的矩形走**，在测量阶段不参与谈判〔C-38〕。
- **屏幕效果不是普通视觉。** 那三类是 `PostProcess` 类，读写屏幕，和合批路径不是一回事〔C-36〕。
- **`CanvasRenderTargetPreviewer` 画的是另一个画布**，不是当前控件的内容。
- **要一个能被点中但什么都不画的区域，用 `Empty`；连命中都不要的容器，就别挂视觉**〔C-96〕。
- **`AddChild` 返回 null 时先查 `HasPanelSlots`**，别当错误处理〔A-91〕。
- **「我没设尺寸，它为什么是这个大小」要先看父容器问了什么**〔C-30〕。
- **自身布局管自己，管不到孩子。** 想让某个孩子变大变小，那是布局容器的事〔C-26〕。
- **自身布局不在 `.dui` 的注册标签里。** 已注册的是 25 个控件标签与 19 个视觉标签，里面都没有它〔A-41〕〔A-42〕。

## 怎么用

一个 `.dui` 片段同时用上三样：

```text
VerticalBox Root {                 // 布局容器：竖排
    Spacing = 24
    Padding = (48, 32, 48, 32)

    Widget Card {                  // 纯容器：没有视觉，就是个矩形
        + UI.LayoutSelfSpacer {}   // 自身布局：占位撑开（标签名未核，见下）
        AnchorData.SizeDelta = (420, 220)

        Image Backdrop {           // 视觉：铺满 Card 的底板
            Brush.TintColor = #1B1E26FF
            AnchorData.AnchorMin = (0, 0)
            AnchorData.AnchorMax = (1, 1)
            AnchorData.SizeDelta = (0, 0)
        }

        HorizontalBox {            // 布局容器：横排
            Spacing = 8
            Native.Toggle Mute { OnToggleChanged -> HandleMuteChanged }
            Text { Text = "静音" }
        }
    }
}
```

⚠️ 上面 `+ UI.LayoutSelfSpacer {}` 那一行的**标签名未核实** —— 自身布局不在已注册的 25 个控件标签与 19 个视觉标签里〔A-41〕〔A-42〕，而 `+ Class { }` 挂的是行为或容器〔C-26〕。用之前先确认。

C++ 走组件那一套：

```cpp
Widget->AddComponent(UDreamLayoutSelfSpacer::StaticClass());
```

## 还没核实的

- **运行时换视觉**的入口（有没有对应的 setter 或组件替换 API）**未核**。
- **`.dui` 里怎么挂自身布局**（不在 25 + 19 个注册标签内，写法未核）。
- 19 个视觉标签与 4 个自身布局变体的**逐项属性**没采 —— 那是 `Docs/Reference/` 82 个类页的活。
- 哪些容器会**自动**给孩子的 `LayoutSelf` 换掉（未核）。

# 4 · 布局引擎与面板基类

> 本章讲「布局在内部怎么跑」。和 §3 的分工是：**§3 讲每个子对象是什么，本章讲它们共用的那一层机器。**
> 功能总清单里的 **#121 布局引擎**与 **#122 几何与测量函数库** 之后会并入本章。

## 15 个容器共用一层基类

继承树只有两层〔B-12〕：

```text
UDreamLayoutContainer                       布局容器基类
└─ UDreamPanelLayoutBase                    面板基类
   ├─ CanvasPanel      ├─ Overlay      ├─ StackBox ─┬─ HorizontalBox
   ├─ WrapBox          ├─ GridPanel                ├─ VerticalBox
   ├─ UniformGridPanel ├─ SizeBox                  └─ ScrollBox
   ├─ ScaleBox         ├─ SafeZone
   ├─ WidgetSwitcher   ├─ Border       └─ MenuAnchor
```

`StackBox` 是唯一一个自己带分支的节点 —— `HorizontalBox`、`VerticalBox`、`ScrollBox` 都从它派生〔B-12〕。

一整个布局层次都写在**同一个头文件**里：`Public/Core/Components/DreamPanelLayouts.h`，1476 行以上〔B-12〕。

## 面板基类提供的子节点 API

12 个，所有容器共用同一套〔B-13〕：

| 函数 | 做什么 |
| --- | --- |
| `AddChild` | 挂上，返回孩子的槽（也可能是 null） |
| `RemoveChild` / `RemoveChildAt` | 分离，**孩子保活**，所有权交给调用方〔B-16〕 |
| `ReplaceChildAt` | 换掉某个位置上的孩子 |
| `DestroyAllChildren` | 拆掉所有孩子 |
| `GetAllChildren` / `GetChildAt` / `GetChildIndex` / `GetChildrenCount` / `HasAnyChildren` / `HasChild` | 查询 |
| `RequestLayoutRefresh` | 请求重排〔B-16〕 |

## 孩子列表只有一份，它归控件

上面那一族查询**转发给拥有这个容器的那个控件**，面板自己不存孩子列表〔B-14〕。理由参考页写得很直白：

> 层级属于 `UDreamWidget`，而**面板上再存一份孩子列表，是唯一保证会和它不一致的东西**。

## 三处「一次替一族」

三处的成因是同一个：**这里只有一个槽类、一份层级**〔B-15〕。

| UMG | 这里 | 为什么 |
| --- | --- | --- |
| `AddChildTo<Panel>`（每个面板一个） | **一个** `AddChild` | UMG 每个面板各有自己的槽类，所以得带类型；这里只有一个 `UDreamPanelSlot`，一个动词就够 |
| `ClearChildren` | **`DestroyAllChildren`** | UMG 的只分离并交给 GC —— 在这里会**留下活的已注册控件、没人持有**，所以这个名字是「按它**必须**做的事」起的 |
| `ReplaceOverlayChildAt` + `ReplaceStackBoxChildAt` | **一个** `ReplaceChildAt` | 两个面板各自的特例，合起来一次给所有面板 |

## 什么时候它不好用

- **`AddChild` 返回 null 时别当失败。** 面板基类把 null 的完整解释指回 `UDreamWidget::AddChild`：控件可以没有布局容器也收孩子，而柔性盒与网格不给槽〔B-16〕。
- **换孩子用 `ReplaceChildAt`，别在同一个位置「先删后加」** —— 那是 UMG 才需要的两步〔B-15〕。
- **别在面板上找孩子列表** —— 它不在面板上，转发给了控件〔B-14〕。
- **这一层不是给业务代码直接用的。** `UDreamPanelLayoutBase` 是抽象基类，你实际碰到的是那 15 个具体容器〔B-12〕。

## 还没核实的

- `RequestLayoutRefresh` 的**触发时机与失效粒度**（整棵树还是只有这一支）**未核**。
- 面板基类把「不许重复添加同一个孩子」这类约束放在**哪一层**（`UDreamWidget::AddChild` 还是面板类里）**未核**。
- 15 个容器里除 `StackBox` 之外的**分支关系**未逐个核（只核到「全部派生自面板基类」）〔B-12〕。
- `EDreamLayoutInvalidation` 的**完整取值**未采 —— 目前只见 `Measure` 与 `Arrange` 两个值〔B-13〕。

# 5 · 行为与生命周期

> 功能总清单 **#11 行为组件数组**。这一章后面会接 **#188–#193** 那批 `UI*` 行为（按钮、开关、滑条……）—— 它们是这一层基类的具体实现。

## 两条并行的子对象基类

挂在控件上的子对象有**两条**基类链，重量不同〔B-24〕：

| | **重的**：`UDreamUIBehaviour` | **轻的**：`UDreamWidgetSubObjectBehaviour` |
| --- | --- | --- |
| 类标记 | `ClassGroup=(DreamGUI)`、`DefaultToInstanced`、`Abstract`、**`Blueprintable`**、`DisplayName="DreamUI Behaviour"` | `BlueprintType`、`Abstract`、`DefaultToInstanced`、**`EditInlineNew`**（**没有** ClassGroup、**没有** Blueprintable） |
| 基类 | `UObject`（尽管 `#include` 了 `Components/ActorComponent.h`） | `UObject` |
| 提供什么 | 完整生命周期 + `Tick` + 7 个变更回调 + 13 个蓝图事件 + 两个性能声明 | 只有 `OnRegister` / `OnUnregister`、`BeginPlay` / `EndPlay`、`IsRegistered`、`GetWidget`、`GetPathDisplayName` |
| 谁走这条 | 画布、`UI*` 行为、网格修改器、导航作用域……〔C-40〕 | **面板槽**（见 §3）〔B-01〕 |
| 文件头版权 | `Copyright 2019-Present Lex Liu` + **`Modified by TypeDreamMoon.`** | 只有 `Copyright 2019-Present Lex Liu` |

挑哪条：**会每帧跑、或者要听控件变化的，走重的；纯粹是「挂在控件上的数据与逻辑」，走轻的。**

## 生命周期：六个时机

六个 `protected virtual`〔B-18〕：

| 时机 | 什么时候发生 |
| --- | --- |
| `Awake()` | 控件**创建**时，像 `BeginPlay` |
| `OnEnable()` | Awake 之后**若 `WidgetActiveInHierarchy` 为真**；或它**变成真**的那一刻 |
| `Start()` | **第一次 `Tick` 之前** |
| `Tick(float DeltaTime)` | 每帧 |
| `OnDisable()` | `WidgetActiveInHierarchy` **变假**时；**或 `OnDestroy` 之前** |
| `OnDestroy()` | 控件销毁时 |

`OnEnable` / `OnDisable` 认的是 `WidgetActiveInHierarchy`（层级折叠后的「激活」），不是可见性 —— 和 §1 里那个 `bWidgetActive` 是同一个开关〔C-35〕。

## `Awake` 的顺序：层级高的先跑

**挂在根控件上的脚本最先执行**〔B-19〕。

这条注释在同一个头文件里**出现三次** —— 是本文件里唯一被重复强调三遍的规则。

## 七个变更回调

| 回调 | 什么时候来 |
| --- | --- |
| `OnTransformChanged()` | 控件的变换变了 |
| `OnDimensionsChanged(bool PivotChanged, bool WidthChanged, bool HeightChanged)` | `AnchorData` 或缩放的哪一部分变了 —— **逐项告诉你变了哪个** |
| `OnChildDimensionsChanged(UDreamWidget* Child, ...)` | **某个孩子**的尺寸变了 |
| `OnAttachmentChanged()` | 挂到了新父级 |
| `OnSiblingIndexChanged()` | 在兄弟里的位置变了 |
| `OnInteractableChanged(bool)` | 可交互状态变了 |
| `OnRaycastableChanged(bool)` | 可命中状态变了〔B-20〕 |

还有一个 `CallbacksBeforeAwake` 缓存：**有些 UI 回调想先于 `Awake` 跑**，但多数行为应该在 Awake 内或之后，所以这些回调先缓存起来、等 `Awake` 时才执行〔B-20〕。

蓝图侧是 **13 个 `Receive*` 事件**（6 个生命周期 + 7 个回调），全部是 `BlueprintImplementableEvent`，而且它们显示出来的名字**不带 `Receive`**（`ReceiveAwake` 在蓝图里就叫 `Awake`）〔B-21〕。

## 两个「声明我不用」的性能开关

`DeclareTickUnused(InClass)` 与 `DeclareTransformChangedUnused(InClass)`〔B-22〕。在构造函数里声明之后：

- 恰好是这个类的行为（以及由它派生的蓝图）**不进 UI 管理器的 tick 列表**，而不是每帧被白叫一次；
- 或者**不听控件的移动通知** —— 连带的效应是：**没人听它移动的控件不会被通知移动**，而「只跟着渲染层移动的控件」也就不会被合成。

两处限制要记住：

- **只覆盖「恰好是 `InClass`」这一个类。** C++ 子类可以重写 `Tick`，而**没有任何东西能替它声明** —— 子类照旧 tick，直到它自己的构造函数也声明一次。
- **它不改变「可不可以 tick」。** 那是 `SetCanExecuteTick` 管的；而且**蓝图写了 `Tick` 事件照旧算数**（`HasTickWork() = !bNativeTickUnused || bHasBlueprintTick`）。

## 怎么调组件

六个 API〔B-25〕：`AddComponent(TSubclassOf<UDreamUIBehaviour>)`（返回新组件）、`GetComponent`、`GetComponents`、**`GetComponentByInterface(UClass*)`**、`RemoveComponent`、`MoveComponentToIndex(Component, NewIndex)`。

`GetComponentByInterface` 是按**接口**取的那一档 —— 不必知道具体类。

## 什么时候它不好用

- **`Awake` 的顺序由层级决定，不由添加顺序决定。** 想让某个行为先跑，改层级，别改添加次序〔B-19〕。
- **`OnEnable` / `OnDisable` 可能不配对。** `OnDestroy` 之前一定会走一次 `OnDisable`，所以「`OnDisable` 了但没有 `OnDestroy`」是正常情况〔B-18〕。
- **别在重行为里做轻事。** 只存数据、不要每帧跑的子对象，走轻的那条基类，别让它进 tick 列表〔B-24〕。
- **`DeclareTickUnused` 不管子类。** 如果你自己写了个中间基类又加回 `Tick`，要在那个类的构造函数里再声明一次〔B-22〕。
- **这一段没有「和 UMG 对照」可写。** `DreamWidget.md` 的 76 行 UMG 对照里**一条讲组件的都没有** —— UMG 没有对应物〔B-25〕。

## 还没核实的

- **两条基类谁更常用**：15 个容器之外，插件里哪些类走重的那条、哪些走轻的，**没逐个数过**〔B-24〕。
- `GetMaxWidgetChildren()` 除 `INDEX_NONE` 之外**有哪些实现会返回真值**，未核〔B-23〕。
- `ECallbackFunctionType` 里那个多出来的 `OnWidgetActiveChanged` **由谁触发、有没有对应的 C++ 虚函数**（回调表里没有它），未核〔B-20〕。
- `PostDuplicate` / `BeginDestroy` 两条注释提到 `DreamUI::ReportCopiedIntoPlaySession` 与 `DreamUIGone` 两个内部机制，**未展开**〔B-17〕。

# 6 · `.dui` 语言（上）：文件、节点与值

> 功能总清单 **#263–#267**。这一层的全部依据是仓库内的语言手册 `Docs/DuiLanguage.md`（**1075 行**）—— 这套语言唯一的一份权威全文。
> 语言分三章：**上（本章）结构与值**、**中 复用**（`+ Class`、样式、资源、`use`、组件）、**下 行为**（绑定、路由、`if`/`for`、`rows`、时间轴、写回、诊断码）。

## 一个 `.dui` 文件是什么

它是 DreamGUI 控件蓝图的**源码**：一棵控件树、它的属性、它的绑定与动画，以**文本**形式存在〔B-26〕。

蓝图把这个文件记为它的 *Source File*；**编译蓝图就是读这个文件**；设计器的改动**写回**这个文件。三件事说的是同一棵树，不是三份。

## 文件放哪、路径怎么写

放在 **`DUI/` 目录**下 —— 项目的（`<Project>/DUI/`）或某个**已启用插件**的（`<Plugin>/DUI/`）。**不在 `Content/` 下**，因为手动里写得很直白：**`.dui` 是源码，不是资产**〔B-27〕。

指向另一个文件的路径（蓝图 Source File 里、或 `use` 之后）有**三种拼写**〔B-28〕：

| 写法 | 意思 |
| --- | --- |
| `Panels/Settings.dui` | 相对某个 `DUI/` 根：**先项目、再各插件，取第一个有该文件的** |
| `Plugin.MyPlugin:Panels/Settings.dui` | 指定那个插件的 `DUI/` 目录 |
| `D:/Work/Proj/DUI/Panels/Settings.dui` | 绝对路径，照写 |

## 文件结构：顶层的八种语句

一条语句到**行尾或 `;`** 结束；注释是 `// …` 到行尾，与 `/* … */`〔B-29〕。

| 语句 | 做什么 |
| --- | --- |
| `class /Game/UI/WBP_Settings` | 这个文件是**哪个**蓝图的源码。**至多一个** |
| `use …` | 把另一个文件或类引进来 |
| `resources { … }` | 具名常量 |
| `props { … }` | 这个文件的类**声明**的属性 |
| `events { … }` | 这个文件的类**抛出**的事件 |
| `viewmodels { … }` | 这个文件的类持有的视图模型 |
| `style Name { … }` | 具名的一组行 |
| `timeline Name { … }` | 一段动画 |
| **一个节点** | 树的根 |

**这些语句的顺序是自由的** —— 一个样式可以声明在穿它的节点**下面**〔B-29〕。

编译成类的文件**恰好一个根节点**（否则 DUI2006）；**没有根的文件是一个「库」**：它能被 `use`，**不能被编译**〔B-29〕。

`class` 行干两件事〔B-30〕：说清这个文件是给**哪个**蓝图的（编译进另一个会 **DUI6003 警告**），以及 —— 这一件更容易被忽略 —— **它的路径就是文件里每一个本地化字符串的命名空间**，这样文件改名时本地化键仍然稳定。没有 `class` 行时，**文件自己的名字**当命名空间。

## 节点与 id

一个节点是**类型 + id + 可选块**。块里可以按**任意顺序**放：属性、`@slot` 行、`+ 组件` 块、子节点，以及控制语句 `if` 与 `for` / `each`〔B-31〕。

```text
Text Title {
    Text = "Settings"
}
```

**无话可说的节点不需要块** —— 一行只写 `Image Divider` 就是一个节点〔B-31〕。

**id 就是节点的身份**，它同时承担四件事：给控件命名、做蓝图图表读的那个**类成员变量**、做绑定解析穿过的**键**、做节点字符串的**本地化键**〔B-32〕。四重身份决定了三条规则：

- 它得是 **C++ 标识符**（字母、数字、`_`，不以数字开头）—— 违规是 DUI3002。⚠️ **ASCII 之外的字符算字母，所以 id 可以是中文。**
- 在文件里**唯一，且比较时不分大小写**（DUI3001）—— 因为它变成的变量是 `FName`，而 `FName` 忽略大小写。
- 不能是关键字：`class`、`style`、`resources`、`slot`、`for`、`each`、`in`、`was`、`use`、`timeline`、`external`、`ease`（**12 个**）。

id 后面可以跟**两个子句，顺序任意**〔B-33〕：

| 子句 | 做什么 |
| --- | --- |
| `: StyleName` | 节点穿上一个样式 |
| `(was: OldId)` | 节点**改过名**：**下一次编译**把所有指着旧 id 的东西 —— **图表引用、绑定、动画轨** —— 搬到新 id 上 |

`(was:)` 要**留到文件至少编译过一次**；第二次改名保留**第一个**旧 id。一次改名被拒有四种方式（DUI3010–DUI3013）〔B-33〕。

## 没写 id 的节点

前提是：**类型后面跟着块或样式子句**。满足时解析器会给它一个自己的 id，形如 **`<parent id>__<type><n>`**〔B-34〕：

- 最近一个**有 id** 的外层节点的 id（没有就是 `Root`）
- 两个下划线
- 类型里**每一个不能出现在 id 里的字符**换成 `_`
- 同类型中**早于它的无名兄弟个数**

`Root__HorizontalBox0` 下第一个无名 `Text` 就是 `Root__HorizontalBox0__Text0`〔B-34〕。

**同样的文本永远给出同样的 id** —— 所以只要文件形状不变，无名节点和显式写的 id 一样稳定。但在其中一个前面**插入一个同类型的无名兄弟，会把后面的全部重编号**〔B-34〕。

三条限制〔B-35〕：

- 它**仍然有类成员变量**（运行时要靠它找回绑定的控件），但是**隐藏的：蓝图图表看不见它**。代码要用这个节点，就得给 id。
- **不能带 `(was: …)`**（DUI2004）—— 没有旧 id 可以改。
- **一行只写一个类型**（没有 id、没有块、没有样式，比如光秃秃的 `Text`）**仍然报错 DUI2004** —— 因为它很可能是**漏了 `=` 的属性**。

## 节点类型按六步解析

一个节点的类型是什么意思，按这个顺序决定〔B-36〕：

| 步 | 是什么 | 例 |
| ---: | --- | --- |
| 1 | **内置标签** | `Widget`（有矩形、没有视觉的普通容器），或某个视觉的标签 |
| 2 | **布局容器** | `VerticalBox`、`Overlay`、`GridPanel`…… 15 个之一 |
| 3 | **组件别名** | `use … as` 给的名字（`Row`），或命名空间带来的（`nier.Row`） |
| 4 | **`@Name`** | `resources` 里 `Asset` 条目的控件类 —— **旧的短名写法**，`use … as` 才是该用的 |
| 5 | **注册表标签** | `Scope.Name`；插件的控件都在 `Native` 下，**25 个** |
| 6 | **资产路径** | `/Game/UI/WBP_Row`；原生类写 `/Script/MyGame.MyWidget` |

第 2 步有个好用的等价关系：**容器型节点就是「一个普通控件驮着那个容器」**，它自己的行**既设容器的属性、也设控件的属性**〔B-36〕。

```text
VerticalBox Categories : Lists {
    Spacing = 29
    Row Audio { Label = "Audio" }
}
```

和 `Widget Categories : Lists { + VerticalBox { Spacing = 29 } … }` 是**同一棵树**〔B-36〕。控件与容器同名时**控件的赢**；在一个容器型节点上再挂一个容器是 **DUI5022**〔B-36〕。

⚠️ **因为标签与容器先被问，别名永远改不了 `Text` 或 `VerticalBox` 的含义** —— 试图改会被拒（DUI3018）〔B-36〕。

## 属性与值

属性名可以是**被反射的属性**，也可以是**点路径**进结构体〔B-37〕：

```text
Name = Value
AnchorData.SizeDelta = (400, 240)
```

裸名字的查找顺序是 **控件 → 视觉 → 容器（只有容器型节点才问）→ 行为**，**第一个有它的赢**。都没有则报 **DUI4001**，并且**给出最近的匹配**〔B-37〕。

**一个块里同名属性，后面的行胜；节点自己的行胜过它样式的行**〔B-37〕。

值的种类是**八种**〔B-38〕：

| 种类 | 例子 | 注意 |
| --- | --- | --- |
| 数字 | `24`、`0.95`、`-3`、`1e-45` | 按属性的数值类型读 |
| 字符串 | `"Settings"`、`"a \"quote\""` | 转义 `\"` `\\` `\n` `\t` `\r`；**在 `FText` 上会被本地化** |
| 颜色 | `#FFF`、`#FFFF`、`#1E1E1E`、`#1E1E1EFF` | 3 / 4 / 6 / 8 位十六进制，sRGB |
| 元组 | `(400, 240)`、`(0, 8, 0, 0)` | 向量、margin、rotator…… 看属性是什么结构体；**可以跨行** |
| 单词 | `Left`、`Collapsed`、`true`、`None` | 枚举值、布尔，或 `None` 表示空引用 |
| 资产路径 | `/Game/UI/T_Icon`、`"/Game/UI/T_Icon.T_Icon"` | 加引号也行 |
| 资源 | `@Accent` | `resources` 条目的值 |
| **节点 id** | `CheckMark` | 在持控件 / 视觉 / 行为的属性上，写本文件里某个节点的 id |

⚠️ **flags 枚举没有 `|`** —— 组合要写成**各位相加的那个数字**〔B-38〕。

字符串可以带上自己本地化用的键：`Text = "OK" @key("Dialog.Confirm")`。不给的话键按 `<节点 id>.<属性>` 生成（在 `+` 块里还要在中间夹上组件类与位置），命名空间来自 `class` 行〔B-38〕。

## 插槽行 `@slot` 与 `@fill`

父级是一个**会排孩子的面板**（盒、网格、叠层）时，里面的节点有一个**面板槽** —— 也就是「父级怎么放我」。`@slot` 行设置它〔B-39〕：

```text
Text Label {
    @slot HorizontalAlignment = Fill
    @slot Padding = (0, 4, 0, 4)
}
```

几行可以收进一个块，用的是 `+` 块的属性语法〔B-39〕：

```text
@slot { SizeRule = Fill  Padding = (0, 8, 0, 0) }
```

盒式布局最常用的那两行还有**简写**〔B-39〕：

| 简写 | 等于 |
| --- | --- |
| `@fill` | `@slot SizeRule = Fill` |
| `@fill 2` | `@slot SizeRule = Fill` 加上 `@slot FillWeight = 2` |

`@fill` 单独占一行（或者只带它的权重）。**在父级不排面板的节点上写 slot 行是 DUI5003**〔B-39〕。

## 一个最小的完整文件

```text
class /Game/UI/WBP_Hello

VerticalBox Root {
    AnchorData.AnchorMin = (0, 0)
    AnchorData.AnchorMax = (1, 1)
    AnchorData.SizeDelta = (0, 0)
    Spacing = 12

    Text Greeting {
        Text     = "Hello, DreamGUI"
        FontSize = 32
        @fill
    }
}
```

逐行要对上的东西：

- `class` 行说明它是给哪个蓝图的，同时定下本地化命名空间〔B-30〕。
- `Root` 四个锚点推到两端、`SizeDelta` 归零，所以它**铺满父级**〔C-28〕；`Spacing` 是它驮着的那个容器的属性〔B-36〕。
- `Text Greeting` 的类型走第 1 步（内置标签），`Greeting` 是 id〔B-36〕。
- `Text` 与 `FontSize` 是属性，裸名字先在控件上找、再在视觉上找〔B-37〕。
- `@fill` 是 `@slot SizeRule = Fill` 的简写〔B-39〕。

手册末尾还有一个**三文件的完整示例**（组件 / 库 / 屏幕），比这个骨架完整得多，值得单独读一遍。

## 什么时候它不好用

- **顺序自由，但结构不是自由的。** 顶层语句随便排，可「编译成类必须恰好一个根」是硬的〔B-29〕。
- **无名节点的 id 会漂。** 在同类无名兄弟前面插一个，后面的全部重编号，引用它们的地方就断了。要稳定就给 id〔B-34〕。
- **无名节点在蓝图图表里看不见。** 那个隐藏变量只有运行时的绑定穿得过去〔B-35〕。
- **别名改不了内置名。** 想拿 `Text` 当自己组件的名字会被拒（DUI3018）〔B-36〕。
- **flags 枚举没有 `|`。** 得自己把各位加起来〔B-38〕。
- **`(was:)` 不能写完就删。** 要留到文件编译过一次〔B-33〕。
- **`.dui` 不是资产，不放 `Content/`。** 「都塞进 Content」的习惯在这里要改〔B-27〕。

## 还没核实的

- **`@slot` 块里到底能写哪些属性**（是否就是面板槽那 17 个）**未核**〔B-39〕。
- **`DUI/.dui-symbols.json` 的实际内容**没读过 —— 只知道它列出每个标签、容器与注册控件及其属性〔B-40〕。
- 手册末章那个**三文件完整示例**，本轮只读了它的结构，**没有逐处核过语法**。
