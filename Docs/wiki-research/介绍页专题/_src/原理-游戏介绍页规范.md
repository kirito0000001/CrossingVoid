## 附 · 萌娘百科规范原文（2026-10-08 直抓验证）

> 抓取路径：`https://zh.moegirl.org.cn/萌娘百科:条目格式/游戏` 与镜像 `https://moegirl.uk/User:Go/Form/G`（两份内容一致）
> 说明：主站 `mobile.moegirl.tw` 返回 429，改用上述两个地址成功。

### 一般构成（**完整顺序 · 原文**）

```
{{Video Game Infobox}}（游戏信息）        必填项
首段                                      必填项
【基本介绍（简介）】                       必填项
【角色简介】
【设定简介】
【游戏玩法】
【额外内容】
【游戏评价】
【相关图片】
【衍生作品】
【其他（视情况而定）】
相关家族模板
【注释】
【参考资料】
【外部链接】
分类                                      必填项
```

> **PS1（原文）**：根据作品实际情况可以增删项目、调整顺序；**但必填项的位置固定，且不能删除**。
> **PS2（原文）**：`{{Video Game Infobox}}` **并非强制使用**，可用自定义信息栏模板替代 → **对我们可用普通 Markdown 表格代替**。

### 四个「填写内容」条文的原文要点

| 节 | 原文要求 |
| --- | --- |
| **游戏信息** | 侧边信息栏，由模板实现（可用表格替代） |
| **首段** | 「**一句话简介**」，交代**开发方、发行方、作品类型、运行平台、发售日期**。<br>公式：`《'''作品名'''》是由'''开发方名字'''开发、'''发行方名字'''发行的'''类型名'''游戏，于XXXX年XX月XX日在X平台上发售，是否支持中文。并有（漫画、动画、轻小说）等衍生作品。`<br>补充：「格式并不固定，一句话概括出作品的大概情况即可」 |
| **基本介绍（简介）** | 作品核心简介，一般能在**官网或商店页**找到；若来自其他网站，**需要用自己的话改写** |
| **开发历史** | 「可以从**游戏立项开发**、到游戏正式发售、到后续追加更新内容，**按时间顺序**介绍」 |
| **分类** | 以作品名 / 开发方发行方 / 类型 / 平台建分类 |

### ⚠️ 对本项目最重要的一条结论

**「游戏立项的背景介绍」不是第一步。**

- 位置的**第一步是「游戏信息」（Infobox）**，**第二步是「首段」**，第三步才是【基本介绍】。
- 「立项开发」被写在 **【基本介绍】下的子节「开发历史」** 里，原文措辞是"从**游戏立项开发**、到游戏正式发售、到后续追加更新内容"。

### ⚠️ 首段公式在本项目**不能照抄**

公式假设「有开发方 + 有发行方 + 有发售日期」，但本项目：

| 公式字段 | 原版《电击文库：零境交错》 | 本项目《零境交错：空界幻境》 |
| --- | --- | --- |
| 开发方 | SEGA × 91Act | **作者一人（TFAC-晓桀）** |
| 发行方 | 腾讯极光计划（大陆）/ 隆中网络（港澳台） | **无**（不盈利、无商业发行） |
| 发售日期 | 2018-08-07 | **无正式发售**（测试服持续更新，当前 V0.5.12） |
| 平台 | Android / iOS | **PC + 安卓**（走启动器） |

→ 首段必须**改造**为「原版关系 + 开发方 + 当前状态」的写法，不能套用百科公式。这正是本项目介绍页与通用模板的**分叉点**。

### 2.2 交叉出的**通用分节结构**（多源一致的部分）

| 块 | 萌娘百科 | Fandom | Gamepedia | 是否采用 |
| --- | --- | --- | --- | --- |

| 基本介绍 | ✅ 必填 | — | — | ✅ 采用 |
| 故事背景 | ✅ 设定复杂时"额外介绍" | Synopsis | — | ✅ 采用 |
| 游戏玩法 | ✅ | Gameplay | — | ✅ 采用 |
| 开发历史 | ✅ | Development | — | ✅ 采用 |
| 发行 / 版本 | — | Release | — | ✅ 采用（本项目=版本与获取） |
| 评价 / 获奖 / 销量 | ✅ | Reception | — | ⚠️ **改造**（见 §三-3） |
| 相关图片 | ✅ | — | — | ✅ 采用 |
| 外部链接 | ✅ | External links | — | ✅ 采用 |

> **一致结论**：无论是日式 ACG 百科、欧美 Fandom 系、还是平台官方帮助，**首段都必须是"一句话说清是什么"**，且**必须包含：作品名 / 开发商 / 发行商 / 类型 / 平台 / 时间**。
> 出处：萌娘百科《条目的构成》「首段」节；Fandom Video Game Databank Layout guide「Intro」节；Gamepedia「Your main page」节（原文要求含 wiki 名、游戏名、**developer**、genre）。

### 2.3 关于「首页」与「介绍页」的分工（易混）

- **Gamepedia 原文**把"首段含开发商/类型"的要求写在 **main page（首页）** 上 → 说明**首页首段也承担介绍职能**。
- 但 **Fandom/biligame** 的做法是：首页 = **导航枢纽**（模块化入口），介绍页 = **单个条目**。
- **我们的现状**：`docs/index.md`（大厅）已是导航枢纽 → 因此"游戏介绍"**应该独立成页**，即现有的 `getting-started/what-is-crossing-void.md`。✅ 与现有结构一致，不需要改架构。

### 2.4 反例与坑（检索中明确提到的）

| --- | --- | --- |

| 项 | 实际情况 | 依据 |

| 工程 | Docusaurus，121 页 | `sidebars.js` |

| `status` 取值闭集 | `draft` / `inferred` / `placeholder` / `source-verified` | 全库统计（`draft` 102 / `inferred` 11 / `placeholder` 7 / `source-verified` 1） |

| 首页引用 | 路线一第 4 步、分区卡片 | `docs/index.md:34,102` |

> ⚠️ **结论：`status: active` 在本库 0 命中** —— 新页必须用 `draft`（或 `source-verified`），不能用默认值。

### 验证 2：现有页的反向自查（wiki-write §7）

抽出现有 19 行的首句：

1. 「《零境交错：空界幻境》是以《电击文库：零境交错》为基础继续制作的同人/复兴向项目。」
2. 「一支队伍由三组角色构成……」
3. 「原版《零境交错》的战斗记忆点是主战/援护搭配……」

**读下来是"采集顺序"而不是"阅读顺序"** —— 第 2 条（编队规则）属于**玩法细节**，不该出现在"这是什么游戏"这一层；玩家此刻还不知道"主战/援护"是什么。
**配标题测试**：第 2、3 节都能配出标题，但**它们各自的主题都不是"这是什么游戏"**。
→ **判定：这一页需要重构，不是补写。**

| 特殊性 | 为什么必须写 | 依据 |
| --- | --- | --- |
| **它是"复活 + 重置版"** | 老玩家带着原版记忆来，会把本作当原版；新玩家根本不知道有原版 | 作者置顶动态（`02` 文档） |

## 四、本页的设计结论（写进 `04_草稿.md`）

**R0 主线承诺**：
> 让**第一次听说**这个游戏的人（新玩家或回归老玩家），在 1 分钟内搞清四件事：这是什么、和原版什么关系、谁做的、能玩到什么。

**骨架**（在通用结构上，插入本项目特有的三块）：

1. **一句话首段** —— 作品名/类型/原版关系/作者/引擎（对齐萌娘百科首段规范）
2. **这是什么游戏** —— 类型与核心体验（3 秒三问）
3. **和原版《电击文库：零境交错》的关系** ★ 本项目特有
4. **谁在做这个游戏** ★ 本项目特有（一人/自研/开源/不盈利）
5. **能玩到什么** —— 当前版本与已实现内容（按 `05`/`08` 的版本事实）
6. **接下来看什么** —— 出口链接

**不写**：编队规则、技能点、守备等**机制细节**（属 `combat/` 分区）；**不写**剧情正文（属 `story/`）；**不写**原版 25 部作品清单（属 `references/`）。

## 五、可复用的方法论（下次写任何 wiki 页都能用）

1. **首段公式**：`《作品名》是由 <开发方> 开发、<发行方> 发行的 <类型> 游戏，于 <时间> 在 <平台> 发布。`（萌娘百科规范）
2. **3 秒测试**：读者扫一眼能否回答"什么类型 / 玩什么 / 独特在哪"（TapTap）。
3. **只讲这一层**：介绍页不承担机制页的职责；一条内容只放一处，其余用链接（Fandom SEO 的"避免重复内容"）。
4. **分类名要具体**：不要"内容""热门"（Gamepedia）。
5. **移动端优先**：60%+ 读者用手机（biligame）。
6. **有争议/未定就标注**，不要写成确定事实（本项目尤其：`御坂美琴` 仍在设计阶段）。
