# 第十三轮：修复"排版全丢"事故（Git Bash 路径转换坑）

作者反馈："你这做的就是一坨啊，原来的排版全部都没了"

## 根因（★ 重要，以后必踩）
**Git Bash（MSYS）会把传给子进程的、以 `/` 开头的环境变量值当 Unix 路径自动转换。**

实测：
```
export TEST='/wiki/crossing-void/'                     # shell 里读出来是对的
env TEST='/wiki/crossing-void/' node -e "..."          # node 看到 → C:/Users/.../PortableGit/wiki/crossing-void/
MSYS_NO_PATHCONV=1 env TEST=... node -e "..."          # node 看到 → /wiki/crossing-void/  ✅
```
→ 构建产物里的资源前缀变成 `/C:/Users/liuyu/AppData/Local/Programs/WorkBuddy/resources/vendor/PortableGit/wiki/crossing-void/assets/...`
→ **CSS/JS 全部 404 → 排版全丢**

## 修复
```bash
cd D:/NewData/Wikis/crossing-void-wiki && MSYS_NO_PATHCONV=1 \
  DOCUSAURUS_URL='https://www.crossingvoid.top' \
  DOCUSAURUS_BASE_URL='/wiki/crossing-void/' npm run build
```
产物路径恢复为 `/wiki/crossing-void/assets/...`；重新打包上传替换 → **CSS/JS 均 200**，页面 200

## 顺带踩的坑
- `MSYS2_ENV_CONV_EXCL='*'` 会导致 Docusaurus 的 `clearPath` 触发 WorkBuddy 安全删除 shim 报错 → **只用 `MSYS_NO_PATHCONV=1`**
- PowerShell 工具的 `Compress-Archive` **打包失败（zip 未生成）** → 改用 **Python zipfile** 打包（262 文件 / 1.55 MB，一次成功）
- 部署必须**分步**：① 解压到 Stage ② **验证 Stage 内容与路径** ③ 替换线上 ④ 验证
