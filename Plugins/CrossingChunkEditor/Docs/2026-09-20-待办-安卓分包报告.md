# 待办：安卓平台永远生不出「分包报告」

> 记录于 2026-09-20。**还没修**，先记下来，之后再回来做。
> 同一天已修掉的是「服务器目标」那两格显示（见文末「同日已修」）。

## 现象

二游打包页面把平台切到「安卓」时：

- 报告：**还没有（还没打包过）**（即使那次安卓打包是成功的）
- 基线：0.5 ✓（这个是对的，安卓基线建得出来）
- 「本次新增（未分类目录）」面板：本地图那栏一直是空的，没有未分类清单、没有体积

## 证据

1. 报告目录里只有客户端 Windows 这一份：
   `C:\CrossingVoid\Saved\PackLogs\ChunkReports\` → 只有 `Win64-Client\latest.json`
   （2026-09-19 18:37:34，mode=Base）。**没有 `Android-Client` 目录。**
2. `ManifestHistory\` 里也没有安卓的归档清单：只有
   `StagedFiles_Windows_Client_*`，没有 `StagedFiles_Android_*`。同一个代码块写的，
   一起被跳过了。
3. 但那次安卓打包本身是成功的：
   `Saved\PackLogs\pack-Base-Android-Client-20260919-214530.log` 结尾是
   `ARCHIVE COMMAND COMPLETED` + `BUILD SUCCESSFUL` + `ExitCode=0`。
4. 用页面同样的参数跑状态查询（只读）也能复现：

   ```powershell
   pwsh -NoProfile -ExecutionPolicy Bypass -Command "[Console]::OutputEncoding=[Text.Encoding]::UTF8; & 'C:\CrossingVoid\Tools\Pack-CrossingVoid.ps1' -Status -Mode Base -Platform Android -Target Client -ReleaseVersion ""0.5"" -ArchiveDir ""D:\DabaoV\Crossingvoid"""
   ```

   → `STATUS_REPORT=||False`，`STATUS_BASELINE=D:\DabaoV\Crossingvoid\Release\0.5\Android|True`
   （报告 false、基线 true —— 正是页面上看到的组合）。

## 根因

`C:\CrossingVoid\Tools\Pack-CrossingVoid.ps1` 里，打包收尾那一段（归档 staging 清单 +
调用 `Build-ChunkReport.ps1` 生成报告）整块挂在「产物目录存在」这个判断里：

```powershell
$PaksDir = Join-Path $ArchiveDir "$PlatformDir\$SubName\Content\Paks"   # 约 55 行
...
if (Test-Path $PaksDir) {   # 约 1280 行往里
    ... 容器体积统计 ...
    ... 归档 StagedFiles + 生成分包报告（约 1347-1382 行）...
}
else {
    Write-Host "[警告] 没找到产物目录：$PaksDir" -ForegroundColor Yellow
    Write-Host '       检查 -archivedirectory 与平台目录名。' -ForegroundColor Yellow
}
```

Windows 客户端把 pak 直接落在 `Content\Paks`，所以走得通；
**安卓把 pak 数据打进 APK/OBB（`main.<ver>.<包名>.obb`），产物目录里没有 `Content\Paks`**，
于是直接掉进 `else`：只打一句警告，报告和 StagedFiles 归档一起被跳过。
所以不是"报告被删了"，而是**安卓从来没生成过**。

（顺带：服务器目标（`-Target Server`）走的是另一个分支，它是散件、不分包，
不写报告也不建基线，那是设计如此。）

## 影响

- 页面「报告」与「本次新增（未分类清单 + 体积）」在安卓平台永远空着，看不出这次新增了什么。
- `ManifestHistory` 缺安卓归档，事后没法对照"这次到底哪些文件进了包"。
- 因为体积算不出来，`chunk-report` 那套「和上一次比对了多少」的检查在安卓上等于没有。

## 修复思路（待定，先聊再做）

候选 A（推荐）：让收尾逻辑按平台形态判断，而不是一律找 `Content\Paks`。

- Windows：`<ArchiveDir>\Windows\<Project>\Content\Paks`（现状）
- 安卓：找 `<ArchiveDir>\Android\...\*.obb`（或 APK），从里面读 pak 列表
- 服务器：跳过（保持现状）

候选 B（省事版）：安卓只出「未分类清单」，体积那一列留空并写明"安卓不支持体积统计"。
"未分类清单"其实算得出来 —— UAT 的
`Engine\Programs\AutomationTool\Saved\Logs\PrePak_Android_UFSFiles.txt` 是 cook 阶段就产出的，
跟 Windows 用的是同一份逻辑，只差"每个 chunk 多少 MB"。

候选 C：先只把 `ManifestHistory\StagedFiles_Android_*.txt` 归档补上（把归档和报告拆开，
归档不依赖体积计算），报告体积以后再说。

> 建议先 A 的简化版：把"产物目录判定"和"体积统计"解耦 ——
> 清单照常归档、报告照常出，安卓的体积字段留 `null` 并在页面显示"安卓暂不支持"。
> 这样一次改动同时解决"报告有没有"和"归档有没有"两件事，体积以后再补。

## 同日已修（供参照，别重复踩）

「服务器」平台那两格的显示问题（2026-09-20 已修）：

1. `Pack-CrossingVoid.ps1` 状态模式里，产物路径原本用 `"$PlatformDir*"` 前缀匹配，
   `Windows` 会先于 `WindowsServer` 命中 —— 于是选服务器时显示的是**客户端**产物。
   现在按目标算目录名（Server → `WindowsServer`）。
2. 页面文案：服务器目标的「报告 / 基线」不再显示「还没有（还没打包过）」「还没建」，
   改成「不适用（服务器散件走 git，不分包）」，避免被误认为数据丢了。
